# 问题记录 — P1-22 通过 Open API 调用的会话在聊天页里显示为"定时任务执行中"

> 批次：P1-22（开放平台落地后的回归）
> 日期：2026-10-22
> 关联：`docs/06-实施计划.md` §五·补 P1-22（缺陷修复块）/ §六 施工纪律 3；`docs/02` §4.5 / §4.8、`docs/03` §4.1（P1-6 方案 A 观察流）
> 定位：本文件记录"界面把外部调用误标成定时任务"的现象、根因与修法。计划文件只留一行指针。

---

## 现象

外部系统用 API Key 通过 `POST /open/v1/conversations/:id/chat` 调某个会话。**在平台聊天页打开这条会话**时，
消息流里出现一条用户气泡写着"（定时任务正在运行…）"，会话看起来像"定时任务正在执行"。

## 根因

帧总线（`backend/src/orchestrator/frameBus.ts`）对**所有发起方一视同仁**地广播：

| 发起方 | 写侧 | 帧里有来源吗 |
|--------|------|--------------|
| 界面发消息 `/api/conversations/:id/chat` | `SseChannel#emit` → `publishFrame` | 无 |
| 开放层 `/open/v1/conversations/:id/chat` | 同一条 `streamChatReply` → `SseChannel#emit` → `publishFrame` | 无 |
| 定时任务后台运行 | `scheduledRun.ts` → `publishFrame` | 无 |

`SseEvent`（`shared/src/sse.ts`）没有来源字段，`/active` 也没有。于是 P1-6 的观察 hook
`frontend/src/features/chat/useConversationWatch.ts` 只能**猜**：它把"这里有一条帧、但本页没发起过这一轮"
直接当成定时任务 —— 占位正文写死 `'（定时任务正在运行…）'`。

结论：**帧没有说谎，是文案替它编了来源**。第 4 条发起路径（外部 Open API）上线后，这条猜法立刻显形。

## 修法（让发起方自己说，而不是让读侧猜）

1. **契约**：锁值 `chat.active:{id}` 的快照加 `startedBy ∈ {UI, OPEN_API, SCHEDULED}`（`shared/src/conversation.ts#CONVERSATION_RUN_ORIGINS`），
   `parseActiveSnapshot` 只认取值域内的值，**旧快照 / 值坏 ⇒ `null`（来源不明），不回落成 `UI`**。
2. **写侧三处显式赋值**：
   - `orchestrator/sse.ts#streamChatReply`：有 `openKeyId` ⇒ `OPEN_API`，否则 `UI`（开放层本来就把 Key 上下文透传进来了）；
   - `orchestrator/scheduledRun.ts`：`SCHEDULED`（headless 运行是唯一没有 HTTP 客户端的发起方）。
3. **读侧透出**：`GET /api/conversations/:id/active` 原样带 `startedBy`；开放层 `/open/v1/conversations/:id/active`
   也透出（外部客户端同样要区分"我自己发的那一轮"与"定时任务后台跑的那一轮"），`openapi/open-v1.json` 已重新导出。
4. **前端统一到同一份来源**：
   - `useConversationWatch` 开流前先读一次 `/active`，占位正文按来源选文案（`watchPlaceholderText`），来源不明用中性措辞；
   - store 新增 `runOrigins`，`noteServerRun` / `begin` 一并维护（`begin` 恒为 `UI`，收口时两处一起清）；
   - 会话头部标签（`serverRunLabel`）、消息流尾部状态（`serverRunStatusText`）、输入区状态机（"服务端在跑但**不归本页**"
     ⇒ 显示"正在生成…"、**不给停止键**、发送禁用）、发送被拒时的 toast（`runOriginBusyMessage`）全部按同一来源说人话。

## 自证

`pnpm verify:chat-sse`（107，新增 G6 `runOrigins` / G7 占位文案不得一律说成定时任务 / G8 `startedBy` 降级 / H12 不归本页的输入区）
+ `pnpm openapi:check`（6）+ `pnpm openapi:regression`（24）+ `frame-bus:regression`（6）+ `verify:open-api-ui`（13）
+ `pnpm -r typecheck`（三包 Done）+ 改动文件 `eslint`（无输出）。真跑（真 Key 调用后在聊天页观察文案）留给用户。

## 已知边界

- 帧本身仍不带来源：观察**运行中**的轮次靠开流前那一次 `/active`；若某轮在 `/active` 读完之后才换来源（不可能，
  来源在拿锁时写死），文案会与实际不一致。这条边界写在 `useConversationWatch.ts` 文件头。
- `startedBy` 只服务**文案**，不参与任何权限 / 计费判据（那两件事各有自己的来源字段：`usage_records.channel`、会话归属）。
