## 1. ✅ 坑预判兑现：状态轮询（`docs/06` P0-1-35 坑预判原文）

### 现象（如果照直觉实现）

传完文档 ⇒ 后端把它建成 `PARSING` 并异步跑流水线。用户盯着列表：
**状态永远停在"解析中"**，除非自己按 F5。而"传四格式各 1 → 状态实时流转"是 `06` 的验收原文第 1 条。

### 根因

解析是**异步流水线**（P0-1-17 的 Redis 队列 + worker），上传端点返回那一刻 `status` 恒为 `PARSING`
（`docs/02` §4.6「status 是响应那一刻的值，恒为 PARSING」）。前端不做轮询就没有任何东西会推动它。

### 处置

`knowledgeModel.ts` 里一个**纯函数**（零依赖 ⇒ 断言进无依赖档）：

```ts
export const DOCUMENT_POLL_INTERVAL_MS = 2000

export function shouldPollDocuments(items): boolean        // 本页有 PARSING ⇒ true
export function documentRefetchInterval(items): number | false // true ⇒ 2000；否则 false
```

`api/knowledgeBases.ts` 的 `useDocuments` 直接把它交给 TanStack Query：

```ts
refetchInterval: (query) => documentRefetchInterval(query.state.data?.items),
placeholderData: keepPreviousData,
```

### ⚠️ 反向的那半：**终止条件**（这句 `06` 没写，但它是正确性的一半）

`refetchInterval` 只要返回一个数字就会**一直**轮询。如果只写"有 `PARSING` 就 2s"而忘了终止，
"全部解析完"之后页面会**永远每 2 秒打一次后端** —— 而它**没有任何可见症状**（用户看着一切正常），
只有开 DevTools 的人才会发现。所以判据写成**三态**：

| 输入 | 返回 | 含义 |
|------|------|------|
| `undefined`（还没问到） | `false` | 不轮询 |
| 本页有 `PARSING` | `2000` | 继续轮询 |
| 全部终态 / 空数组 | `false` | **停** |

**判据只有一处来源**：api 层**不自己判** `PARSING`（否则"什么算解析中"会长出第二份实现）——
H3 读源码断言 `useDocuments` 里出现的是 `documentRefetchInterval(` 而不是 `status === 'PARSING'`。

### 顺带：把这件事**写在明处**

详情页表尾有一行「解析中的文档每 **2** 秒自动刷新，全部解析完即停」，读数来自
`DOCUMENT_POLL_INTERVAL_MS / 1000`（H5 守门"这个数字来自常量而不是手写的 2"）。
不自证的话，用户会怀疑"页面是不是卡住了"。

## 2. ⚠️ 验收项与实现互相矛盾：`.doc` 必须留在 `accept` 里

### 现象

`06` 的验收原文第 4 条：**"选 `.doc` 立即提示且不发请求"**。
而后端明确拒收 `.doc`（P0-1-16 的四道前置校验②：400 + 「请另存为 .docx 后重传」）。

### 矛盾在哪

"不支持的格式不该出现在选择器里"是很自然的想法，于是最直觉的写法是：

```tsx
<Upload accept=".pdf,.docx,.md,.txt" />   // ❌ 看起来正确
```

但这样一来，**系统文件选择器会把 `.doc` 过滤成灰色的、用户根本选不中** ⇒
前端那条"立即提示"的分支**永远不执行**，`06` 的第 4 条验收**无法通过**（不是"通过得难看"，是"根本测不到"）。

### 处置

```ts
// knowledgeModel.ts
export const UPLOAD_ACCEPT_ATTRIBUTE = [...UPLOAD_EXTENSIONS, LEGACY_DOC_EXTENSION].join(',')
```

即 **`accept` 里故意含 `.doc`**，拦截交给纯函数 `screenPickedFiles(files)`：

| `code` | 触发 | 提示 |
|--------|------|------|
| `NO_FILE` | 一个都没选 | 请选择一个文件 |
| `MULTIPLE` | 多选 | 一次只能传一个文件（**不是"悄悄取第一个"**） |
| `EMPTY` | 0 字节 | 这个文件是空的 |
| `LEGACY_DOC` | `.doc` | 「暂不支持 .doc（旧版 Word 二进制格式），请另存为 .docx 后重传」 |
| `UNSUPPORTED` | 其它扩展名 / 无扩展名 | 与上面**两条不同的文案**（别合成一句） |

A1 断言的正是"`accept` 里**同时**含四个白名单与 `.doc`"，A3 断言 `.doc` 走专门一类且带上可操作下一步。

### ⚠️ 配套：`beforeUpload` 必须 `return false`

AntD 的 `Upload` 只要 `beforeUpload` 不返回 `false`（也不 `Promise.reject`），就会**自己发一次上传**
（请求打到 `action`/`customRequest`）—— 于是"前端已拦下、没有发起上传请求"变成
"拦下了，但**还多传了一个垃圾请求**"。H4 读源码断言这一行存在。

> 另：`file.size` 的**上限刻意不判** —— `UPLOAD_BODY_LIMIT` 是后端环境变量，前端读不到，
> 前端硬编一个 100MB 就是"第二份口径"。超限由传输层给 413（P0-1-16 已定案）。

## 3. ⚠️ 三处"界面上看着该有、其实拿不到"的数字：一律不造假

这是本批最像 P0-1-34「删会话给不出条数」的一族 —— **"界面上有数字"≠"能拿到这个数字"**。

### ① 全库 chunk 总数（原型上有）

`design/knowledge.html` 的列表页有一列"片段数"（全库总和）。而
`GET /api/knowledge-bases` 的投影里**只有 `documentCount`**（`docs/02` §4.6），
要拿全库片段总数得 `count(*)` 整张 `chunks` 表 —— 那是本仓**最贵**的查询形态（P0-1-28 已为它立过规矩）。

⇒ **界面上不显示这个数**。列表页那一列改叫「文档」（`documentCount`，拿得到）。

### ② 文件 size（原型上有）

`documents` 表**没有 `size` 列**、列表端点也不回。⇒ 文档表格的副标题**只放扩展名**
（`extensionOf(fileName)`，识别不出给 `—`），**不编"1.2 MB"**（A7 守门）。

### ③ 检索结果的「命中库」（`子方案①` §六 B1 要求的新增列）

`POST /api/knowledge-bases/:id/search` 是**库级**端点 —— 库来自**路径参数**，
所以"命中库"这一列**恒等于当前库名**，写着等于零信息量（而且**每一行都一样**）。

⇒ 这一列改名**「来源文档」**（`hitSourceText`）：有 `page` 给"第 N 页"、否则给"第 N 块"。
`docs/02` §4.6 与本文件同步记下这个口径变化（原型的列名不再是界面上的列名）。

## 4. 三态与 jsonb 局部合并：三条"少写一个字就静默出错"的口径

### ① 改库请求体**只在值真的变了才带键**

`buildKnowledgeUpdateBody(current, draft)` 的返回是 `object | null`：

```
没有任何改动            ⇒ null                （调用方据此不发请求，提示"没有需要保存的改动"）
只改了名字              ⇒ { name }            （三态：不带 ≠ 清空）
描述改成空              ⇒ { description: null }（三态里唯一能表达"清空"的写法）
```

⚠️ 少写那个 `null`（写成"空串就不带这个键"）会让用户"删掉描述、保存、刷新后它又回来了" ——
`POST`/`PATCH` 的 `description` 是 `.nullable().optional()`、**没有 `.default()`**（P0-1-15 定案）。

### ② 检索配置是 jsonb **局部合并**，且**两个权重成对带**

`buildRetrievalPatch()` **逐键比较**（只把变了的键放进 patch）。
⚠️ 但 `weights` 在 schema 里要求**同时给 `vector` 与 `fulltext`** —— 只改一个权重时，
patch 里必须**两个键都带**（另一个用当前值），否则后端必 400。E8 专门守这条。

### ③ 建库时**分块参数留空 = 不带这两个键**

`infra/.env` 的 `CHUNK_SIZE_DEFAULT` / `CHUNK_OVERLAP_DEFAULT` 是**服务端的环境级默认值**，
建库时快照进该库（P0-1-15）。前端**读不到**这两个环境变量 ⇒ 表单里两个输入框
**默认留空 + 占位符「留空则用服务端默认值」**，提交时**不带这两个键**。

> ❌ 反例：前端硬编 `512` / `64` 当默认值 ⇒ 用户以为自己选了默认值，实际是**前端替他选了一份**
> （哪天管理员改了环境变量，新库会被前端的硬编值覆盖）。E1 守这条。

## 5. ⚠️ 下载端点是全仓唯一不套信封的端点 ⇒ `requestBlob` 按**响应形状**分支

### 背景

`GET …/documents/:docId/download`：**成功返回字节流，失败才返回 `{code,msg,data}` 信封**
（P0-1-21 定案，是本仓唯一这样的端点）。

### 错法

```ts
// ❌ 按状态码判
if (res.status !== 200) throw await toApiError(res)
return await res.blob()
```

这条在"成功但 body 恰好是 JSON 文本"（例如下载一个叫 `data.json` 的 `.txt`… 不，是任何
内容像 JSON 的文本文件）这类边界上会**静默分叉**：状态码是 200、内容却是 JSON，
按状态码判的实现会把它当字节流传下去（这半边其实对），而反过来"失败时状态码不是 200 就直接抛"
在**代理/网关改写状态码**时会漏判。

### 处置：按 `content-type` 判

```ts
const contentType = res.headers.get('content-type') ?? ''
if (contentType.includes('application/json')) {
  throw await toApiError(res)     // 是信封 ⇒ 走统一的 unwrapEnvelope 路径
}
return { blob: await res.blob(), fileName: fileNameFromContentDisposition(res.headers.get('content-disposition')) }
```

**这是全前端唯一"跨出 `unwrapEnvelope`"的地方**，写在 `api/client.ts` 的文件头里。

### 文件名：`filename*` 优先于 `filename`

`Content-Disposition` 是 **RFC 6266/5987 双写**（P0-1-21）：`filename="<ASCII 回落>"` +
`filename*=UTF-8''<百分号编码>`。**中文名只有 `filename*` 是对的** ——
取错会得到一个 `%E5%8F%98%E6%9B%B4...` 这样"能下载、但文件名是乱码"的结果（用户不会报 bug，只会自己改名）。

`fileNameFromContentDisposition(header)` 的判据：

1. 先找 `filename*=UTF-8''<enc>`（**三段式**；畸形 —— 缺那两个单引号 —— 就退回第 2 步）
2. 再找 `filename="<...>"`（也支持不带引号的 token）
3. 都没有 / 解析不出 ⇒ **返回 `null`**（**不抛错**）⇒ 调用方退回文档自己的 `fileName`

I1~I4 四组边界全在无依赖档里。

## 6. ⚠️ 两种"给不出数字"的处境，要分开处理

| | 删**知识库** | 删**会话**（P0-1-34） |
|---|---|---|
| 界面能不能给出"将删除 N 篇/条" | **能**：`GET /:id` 回 `documentCount` / `agentCount` | **不能**：`GET /:id/messages` 是**游标分页**，只回 `{items,nextCursor,hasMore}`（**没有 `total`**） |
| 界面怎么写 | 如实写「将删除 **N** 篇文档」 | 只能写「**全部消息**」，真数进**成功提示** |
| 参考 | `DeleteKnowledgeBaseModal` | `DeleteConversationModal` |

**同一原则、两种处境** —— 关键是**先看数据源有没有这个数**，而不是"原型上写了就照抄"。

### 顺带：`agentCount > 0` 时**不禁用删除**，而是给提示 + 指路

后端在"库被某个智能体引用"时回 **409**（`agent_components.ref_id` 是多态外键、没有 DB 兜底，
P0-1-15 定案）。前端有 `agentCount`，所以能在**点之前**告诉用户：

- 弹窗里出错误级提示 + 一个指向 `/agents` 的链接（"先去解绑"）
- **确认按钮禁用**（否则用户点下去只会拿到一句 409，而"要先去哪解绑"得自己猜）

⚠️ 这与 P0-1-34「**刻意不因"正在生成"禁用删除**」并不矛盾：那边后端**不**拦（用户要能清理自己的历史），
前端再拦就是自己发明约束；这边**后端确实会拦**，前端拦是**如实转达**。

### 级联那一档的形态（沿 `docs/03` §七）

`Tag tag--danger`「级联删除」+ 明示影响范围 + **输入库名逐字确认**
（`isKnowledgeDeleteConfirmed(input, name)` —— **刻意不做 `trim`**，多一个空格都不算）+ **失败不关弹窗**。
G5 断言逐字语义。

## 7. 检索测试抽屉：三处"别替用户做决定 / 别把两个意思画成一个样"

### ① `mode` / `topK` **默认"跟随该库配置"**（不预选）

抽屉里这两个控件是**可覆盖该库快照**的（`docs/02` §4.6 检索契约：只有 `mode`/`topK` 能覆盖）。
如果给它们**预选** `HYBRID` / `10`，用户会**永远观察不到库级配置是否生效**：
在「检索配置」里把 `mode` 改成 `FULLTEXT`、再来抽屉一搜 —— 看到的还是混合结果，
而用户会以为"配置没保存"。

⇒ 两个控件的默认值是 `undefined`/`null`（= 不覆盖），占位符写明「跟随该库配置」。

### ② 结果区回显**服务端生效值**

顶部一行显示 `mode / topK / rrfK / candidatePool / elapsedMs / 命中数` —— **全部来自响应**。
这样"我改的配置真的生效了"有可见证据（只显示自己输入的值等于自欺）。

### ③ `null`（未命中）与 `0`（恰好 0 分）**是两个意思**

`docs/02` §4.6 定案：某一路没命中 ⇒ 该路 `score`/`rank` 都是 **`null`（不是 0）**。

| 展示项 | 写法 | 判据 |
|--------|------|------|
| 向量分 / 全文分 | `null` ⇒ `—`；数字 ⇒ 两位小数 | 显示 `0` 会让人以为"两路都算了、只是很低" |
| **RRF 融合分** | **四位**小数（如 `0.0321`） | 它在 **0.03x** 量级（`1/(60+1)≈0.016`）—— 两位小数会把**一屏结果全显示成 `0.03`** |
| 名次 | 数字 ⇒ `#N`；未命中 ⇒ `—` | 不给 `#0` |

**两套小数位**这件事是本批唯一"同一个表格里两种精度"的地方，F2 专门守它。

### ④ 两种空/降级横幅**不是同一句**

- **一条都没命中** ⇒ info 级，说清是"库里没有相关内容"（不是"页面坏了"）
- **向量路被跳过**（库快照的 embedding 模型 ≠ 当前 provider）⇒ **引用服务端 `warnings[0]` 的原文**，
  不重写（那是 `docs/02` §4.6 的降级路径，P0-1-20 定的口径）

## 8. 一处原型口径纠正：库级检索配置**是落库的**

`design/kb-detail.html` 的库级检索配置卡上写着一个标签「**不落库 · 每次请求传入**」。

**它写反了**：

| | 实际语义 |
|---|---|
| 库级 `retrieval_config`（`mode`/`topK`/`score`/`rrfK`/`weights`） | **落库**（`knowledge_bases.retrieval_config` jsonb），是"这个库的检索口径" |
| 抽屉里那个可覆盖的 `mode`/`topK` | "**这次试查**"的属性，**不落库**（P0-1-20 定案：让一次点击改掉别人的召回率比看不到更坏） |

原型把两者说反了。按实际语义改写文案 —— 否则用户会以为"改配置只是临时试一下"。

> 同类：`design/chat.html` 的四态状态灯在 P0-1-34 也被判定为"原型有、数据源没有"⇒ 落成三态。
> **原型是设计稿不是契约**，遇到对不上的地方要按 `docs/02` 的实际契约纠正并**留痕**。

## 9. `formatUpdatedAt` 抽成唯一来源

知识库列表要显示"最近更新"，而 P0-1-31 的 `agentModel.ts` 里**已经有一份**私有实现。

⇒ 抽到 `app/format.ts`：

```ts
export function formatUpdatedAt(iso: string | null): string   // '09-22 15:04'，刻意不用 toLocaleString
```

`agentModel.ts` 改为**重导出**（`export { formatUpdatedAt } from '../../app/format.js'`）——
这样 P0-1-31 页面的 import 路径**一字不动**（否则本批会顺手改一个与它无关的文件）。

H1 断言 `formatUpdatedAt` 的**定义**（`export function formatUpdatedAt`）全仓**恰好一处** ——
与 J4 守 `CONFLICT` 文案是同一手法：**"只许一处写法"的东西，用源码级断言钉死**。
