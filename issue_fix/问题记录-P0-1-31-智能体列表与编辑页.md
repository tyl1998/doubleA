## 1. ⚠️ 已被删除的知识库无法解绑 ⇒ 编辑页被卡死（端测实测的真缺陷）

### 现象
编辑页勾选了知识库 A 之后，从别处（另一个标签页 / 另一个用户）把 A 删掉，再回编辑页保存：`PATCH` 成功，`PUT components` 返回 `404 NOT_FOUND`（引用校验失败）。界面正确地显示了「组件绑定（NOT_FOUND）· 知识库不存在或已被删除」——但**那个知识库的 uuid 在页面上找不到任何对应物**：KB 列表重拉后 A 已不在勾选框里，而它仍在 `selectedKbIds` 里。用户想解绑它，无从下手；每次保存都会重发同一个失败的 `PUT`，永远卡死。

### 根因
知识库多选框的数据源是「当前可见的知识库列表」，已删除（或当前账号看不到）的库不在列表里 ⇒ 已选中的失效引用变成**页面上的幽灵**。`AgentFormPage` 原本只渲染 `kbItems` 里存在的项。

### 修复
对 `selectedKbIds` 与可见库列表做差集，把缺失的渲染成一行特殊的「已失效的知识库 · 需解绑」：

```ts
const kbIdSet = new Set(kbItems.map((kb) => kb.id))
const missingKbIds = kbQuery.data === undefined ? [] : selectedKbIds.filter((id) => !kbIdSet.has(id))
```

```tsx
{missingKbIds.map((kbId) => (
  <Checkbox key={kbId} className="pick" checked onChange={() => toggleKb(kbId, false)}>
    <span className="pick__title">已失效的知识库 <Tag className="tag--danger">需解绑</Tag></span>
    <span className="pick__meta">{kbId} · 它已被删除（或你的账号看不到它）。取消勾选即解绑，然后保存。</span>
  </Checkbox>
))}
```

手法与既有的 `staleModelOption`（模型停用后把旧值留在下拉里）同源：**用户选过的引用不能因为数据源变化而凭空消失**。

### 端测取证
外部删掉 KB3 后保存 ⇒ 后端日志 `PATCH 200 (changed:["name"])` → `PUT 404 NOT_FOUND`；界面 `components dirty=true failed=true`；解绑失效库后点「重试未保存的区块」⇒ 因服务端已是目标状态（无差异）**一个请求都没发**，直接成功回列表。

### 教训
「引用校验失败」类错误的修复入口必须指向**页面上可见的、可操作的东西**。只报 uuid 的错误提示等于没修——用户看到错误却找不到那个 uuid 对应的控件。

## 2. ⚠️ AntD 5 的 cssinjs 运行时注入会压过 `app.css` 里同特异度的规则

### 现象
`styles/app.css` 1024px 断点里的 4 条 `.ant-input` / `.ant-select-selector` 规则**从来没有生效过**（P0-1-30 写下时就是死的，只是当时没有页面用它们，看不出来）。

### 根因
AntD 5 的 cssinjs 在**运行时**把样式注入 `<head>` 末尾，DOM 顺序排在 `app.css` 的 `<link>` 之后。两条选择器特异度同为 (0,1,0) 的规则，后者赢 ⇒ AntD 的内联注入永远压过我们的同权重规则。

### 修复与定案
覆盖 AntD 组件外观的规则**一律加 `:root` 前缀**（抬到 (0,2,0)）。本批补了 `:root .ant-input`、`:root .ant-select-selector` 等 4 处，新增的 Tag 覆盖（`:root .ant-tag`、`:root .ant-tag.tag--accent/.tag--warn/.tag--danger`）与 Checkbox/Radio 的 `.pick` 覆盖同口径。规则已写进 `app.css` 文件头。

### 教训
不是"样式没写对"，而是**样式被注到了后面**。这类问题在 DevTools 里一眼可见（规则被划掉、来源是 `cssinjs`），但只看代码永远发现不了。

## 3. JSX 文本子节点不认 Markdown ⇒ 界面上出现字面的 `**不受影响**`

### 现象
删除确认弹窗里显示 `已经保存成功的部分**不会回滚**` 与字面的 `` `deleted_at` ``（带反引号）。

### 根因
把 Markdown 习惯带进了 JSX：JSX 的文本子节点是**纯文本**，`**xx**` 与 `` `xx` `` 原样显示。

### 修复
全仓扫描 `.tsx` 非注释行里含 `**` 或反引号的 JSX 文本，共修 4 处：`<strong>不受影响</strong>`、`<strong>全部会话</strong>`、`<strong>都不会被删除</strong>`、`<strong>软删除</strong>` + `<code>deleted_at</code>`。

## 4. `useState<AgentItem | null>(null)` 让 `item ?? created` 展宽成 `Item | null` ⇒ TS18047 × 6

### 根因
`item` 是 `AgentItem | undefined`，`??` 之后类型是 `AgentItem | null`；`item !== undefined` 的收窄**收不掉 `null`**，后续 6 处 `created.xxx` 全部报 `'possibly null'`。

### 修复
`created` 的语义本来就是"还没创建"，用 `useState<AgentItem | undefined>(undefined)`。不是加非空断言，而是**把类型的表达改对**。

## 5. 端测脚手架：列表骨架屏的取证方法（可复用）

### 问题
骨架屏的渲染条件是 TanStack Query 的 `isPending`（**首挂载 + 无缓存**）。两条常规路都走不通：
- 切走切回：缓存 `staleTime: 30s` 内直接命中，挂载即有数据；
- `docker pause` 制造慢查询：把 `/api/auth/me` 一起拖慢 ⇒ 整页重载时先卡在 `RequireAuth` 的 boot 屏，列表组件根本没挂载。

### 方案
在 13000 前挂一个**只延迟 `GET /api/agents` 的本地代理**（13001），再起第二个 vite dev（5175，`VITE_DEV_PROXY_TARGET=http://127.0.0.1:13001`）。整页重载 ⇒ boot 屏一闪而过（auth 直通）⇒ 列表页挂载 ⇒ agents 请求挂住 8s ⇒ 骨架屏可见。cookie 不区分端口，5175 直接复用登录态。

### 取证
`{skeleton:true, skelLines:15, busy:true, table:false, boot:false, lead:'正在读取智能体列表…'}`（15 = 5 行 × 3 条，`TableSkeleton` 默认 rows=5）；8s 后切到真实表格，lead 变「你可见的智能体共 N 个…」。**列表三态（空态 / 骨架 / 错误）就此全部有证据。**

### 教训
"拿不到观测"不等于"没实现"。三态里前两态都能自然复现，骨架屏被缓存/boot 屏挡住是**测试环境问题**，用脚手架（慢代理）解决，不为此改产品代码。

## 6. 环境与工具杂项

- **`pnpm -r build` 报 `generated/prisma … doesn't look like a generated Prisma Client`**：上一次并行 build 在 `db:generate` 中途失败留下半个产物。`rm -rf backend/generated/prisma && pnpm db:generate` 后重跑即绿（`generated/` 在 `.gitignore`）。
- **dev `.env` 的 `EMBEDDING_*` 三项为空** ⇒ 建知识库 500。端测用环境变量覆盖启动后端（注入一个永不会被访问的 URL，与 verify 脚本同手法）：`EMBEDDING_MODE=api EMBEDDING_API_URL=http://127.0.0.1:1/v1 EMBEDDING_API_KEY=… EMBEDDING_API_MODEL=…`。
- **建 Provider 的 `type` 枚举是 `['CHAT','EMBEDDING']`**（不是 `OPENAI`），传错吃 400 校验失败（字段级错误在 `data.fields`）。
- **pino 彩色输出混有 ANSI 转义** ⇒ `grep 'method: "PUT"'` 匹配不到日志；用 `sed -n 'X,Yp'` 取行再过滤更可靠。
- **`curl` 打 localhost 必带 `--noproxy '*'`**，否则本地代理环境下 `http=000`。
