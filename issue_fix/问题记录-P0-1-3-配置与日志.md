## 坑 1 — zod `.default()` 被 `.env` 空串绕过（本批最大的坑）

**现象**：`.env` 里 `UPLOAD_BODY_LIMIT=`（照抄样例、留空待填）时，启动直接失败：

```
✖ 后端启动中止：配置校验未通过（共 4 项）
    · SANDBOX_IMAGE   Required
    · EMBEDDING_API_URL   Required
    ...
```

`SANDBOX_IMAGE`、`EMBEDDING_API_URL` 在 schema 里都是**可选**的，`UPLOAD_BODY_LIMIT` 还带默认值 `100MB`
—— 按理都不该拦。

**根因**：`.env` 的 `KEY=` 解析出来是**空字符串，不是 `undefined`**。而 zod 的 `.default()` 只在
**最外层输入为 `undefined`** 时短路：

```ts
// ❌ 看似对，实则空串会绕过默认值
z.preprocess(emptyToUndefined, z.string()).default('100MB')
//   ↑ 输入 '' → ZodDefault 不短路（因为入参不是 undefined）
//             → preprocess 把 '' 变成 undefined
//             → 内层 z.string() 拿到 undefined → "Required"

// ✅ 把「空 → 默认值」前置收口
function defaultedVar<T extends z.ZodTypeAny>(schema: T, fallback: z.input<T>): z.ZodType<z.output<T>> {
  return z.preprocess((value) => emptyToUndefined(value) ?? fallback, schema)
}
```

**两个连带结论**：

1. `fallback` 的类型必须是 **`z.input<T>`（输入类型）而不是输出类型** —— 默认值会**再走一遍内层
   schema**，由它自己校验/变换。第一版用了输出类型，于是字节数变量的默认值传了"已解析好的
   `{raw, bytes}` 对象"，内层 `z.string()` 报 `Expected string, received object`。
2. **必填项要的正是相反语义**：`KEY=` 应被当作"缺失"（放进缺失清单），所以必填项的 helper 里保留
   `emptyToUndefined`，且**不挂默认值**。

> 已写进 `docs/06` §六 施工纪律第 16 条：后续 C 包（模型池）、D 包（知识库）还会写大量 zod schema，
> 同一个坑不必踩第二遍。

## 坑 2 — `process.loadEnvFile` 不覆盖已存在的变量

**实测**（Node v22.22.2）：

```js
process.env.FOO = 'from_env'
process.loadEnvFile('/tmp/.envtest')      // 文件里 FOO=from_file, BAR=from_file
// → FOO = 'from_env'（不被覆盖）  BAR = 'from_file'
```

这正是我们要的 **12-factor 语义**（容器/CI 注入优先），照用即可。但有个**验收上的副作用**：

- 想模拟"删掉必填项"不能靠 `unset`：文件里的值照样会被加载进来（除非 `unset` 后文件里也没有）。
- **改用 `KEY=`（置空）**：空串也算"已存在"，不会被文件覆盖 → 精确地让**只有这一项**缺失：
  ```bash
  REDIS_URL= node backend/dist/backend/src/index.js
  # → 共 1 项：REDIS_URL 未设置（必填）
  ```
- 想验"全裸环境"则用 `DOUBULEA_SKIP_ENV_FILE=1`（一次列出 7 项必填）。

**顺带**：这个开关也是 CI/容器里的逃生口（.env 文件在镜像里通常不存在，`loadEnvFile` 会抛）。

## 坑 3 — pino 的 `transport` 是运行期解析的

**现象/风险**：`pino-pretty` 装在 `devDependencies`，而 pino 的配置是**字符串 target**：

```ts
pino({ transport: { target: 'pino-pretty' } })   // 运行期要求模块可解析
```

生产镜像 `pnpm install --prod` 后没有 `pino-pretty` → **进程启动即崩**。这是个"开发一路顺、上生产才炸"的坑。

**对策**：启动时用 `createRequire(import.meta.url).resolve('pino-pretty')` **先探测**，
解析不到就静默降级为纯 JSON，并把「是否着色」交给 `LOG_PRETTY`（默认跟随 `NODE_ENV`）：

```ts
const transport = createTransport()      // 探测失败返回 undefined
pino({ ...(transport === undefined ? {} : { transport }) })
```

> 只调一次 `createTransport()`：transport 会拉起 worker 线程，重复解析没有意义（第一版在对象字面量里
> 调了两遍）。

## 坑 4 — 产物期的模块路径比源码期深两层

`backend/tsconfig.json` 的 `rootDir` 是 monorepo 根（因 `paths` 把 `shared/src` 纳入编译，见
`问题记录-P0-1-1` 坑 5），于是：

```
源码期   backend/src/config.ts              → ../../infra/.env
产物期   backend/dist/backend/src/config.js → ../../../../infra/.env
```

**对策**：不数层数，**向上找标志文件** —— 遇到含 `pnpm-workspace.yaml` 的目录即工作区根：

```ts
for (let hop = 0; hop < 8; hop += 1) {
  if (existsSync(resolve(dir, 'pnpm-workspace.yaml'))) return dir
  dir = dirname(dir)
}
```

顺带兼容三种场景：`cwd` 在仓库根、`cwd` 在子包、以及 `DOUBULEA_ENV_FILE` 显式指定。
（本机实测产物期、源码期、从 `backend/` 与仓库根分别启动，四种组合都能正确命中 `infra/.env`。）

## 坑 5 — pino 带 transport 时进程不退出

**现象**：骨架期没有 HTTP 服务，打完一行启动日志进程却**一直挂着**。原因就是 transport 的 worker
线程（以及 sonic-boom）持有事件循环句柄。

**对策**：骨架期显式收尾 —— `logger.flush(cb)` 保证日志真的落到 stdout 再退出：

```ts
logger.flush(() => process.exit(0))     // P0-1-4 落地 app.listen 后删掉这两行
```

> 反差：`--check-config` 那条路**刻意用 `console.log`**，既绕开 transport，也保证输出能被
> CI/grep 稳定消费（不受 `LOG_LEVEL`/着色影响）。

## 坑 6 — zod 的 issue 不一定带得出变量名

**现象**：`required_error` 只给「必填」，跨字段校验（如 `CHUNK_OVERLAP_DEFAULT >= CHUNK_SIZE_DEFAULT`）
在对象级 `.superRefine` 里报错时，`path` 是**空的** —— 失败报告就指不到"改哪一行"。

**对策**（让报告可直接照着改）：

1. **schema 键名 = 环境变量名**（不再嵌套分组），`issue.path[0]` 就是变量名，还能与 `.env.example`
   逐行对照；
2. 所有 `ctx.addIssue` **显式给 `path`**：

```ts
ctx.addIssue({ code: z.ZodIssueCode.custom, path: ['CHUNK_OVERLAP_DEFAULT'],
               message: `必须小于 CHUNK_SIZE_DEFAULT（当前 ${ov} >= ${size}），否则分块会退化` })
```

3. 同一变量可能同时报「类型错 + 最小值」，报告按 key 去重只留首条；
4. 报告里给**修法**：必填项配 `ENV_VAR_HINTS`（去哪抄、示例长什么样），
   主密钥直接写 `openssl rand -base64 32`。
