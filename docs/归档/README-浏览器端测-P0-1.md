### 浏览器端测（⭐ 第二个可端测里程碑：P0-1-30 起）

**前置**：`pnpm infra:up && pnpm db:deploy && pnpm db:seed`（拿到 admin / member 的初始密码），

`VITE_DEV_PROXY_TARGET=http://127.0.0.1:13000 pnpm dev:frontend`（5174），然后打开
**`http://localhost:5174/`**。

### 浏览器端测 · 对话（⭐ 第四个可端测里程碑：P0-1-32 起，P0-1-33 补输入区/停止/断线，P0-1-34 补会话侧栏/全屏布局）

**前置**：同上一节（依赖 + 迁移 + 两个进程 + 登录态 + 一个**已经绑了 `type=CHAT` 模型**的智能体）。
要让回答**真的流式吐字并带引用卡**，还要把"模型上游"换成**本仓的假上游** —— 这**不是可选的偷懒**，
而是四档口径（P0-1-12 定案：凡"调用外部服务"的验收都不接真厂商）：

```bash
# ① 起两个假上游（对话 + embedding），**前台常驻**，抄下它打印的两个 URL，Ctrl-C 收工
pnpm serve:upstreams
#   → CHAT_UPSTREAM_URL=http://127.0.0.1:<portA>/v1
#   → EMBEDDING_UPSTREAM_URL=http://127.0.0.1:<portB>/v1
#   ⚠️ 端口是**随机的**，每次起都不一样 ⇒ 第 ② 步必须重新抄一遍

# ② 把 Provider 的 baseUrl 指到 CHAT_UPSTREAM_URL（模型池接口仅 ADMIN）
curl -s --noproxy '*' -X PATCH http://127.0.0.1:13000/api/model-providers/<providerId> \
  -H 'content-type: application/json' --cookie "$ADMIN_COOKIE" \
  -d '{"baseUrl":"http://127.0.0.1:<portA>/v1"}'

# ③ 带 embedding 三项起后端（否则文档走不到 READY、检索拿不到 query 向量）
EMBEDDING_MODE=api \
EMBEDDING_API_URL=http://127.0.0.1:<portB>/v1 \
EMBEDDING_API_KEY=dev-fake-key \
EMBEDDING_API_MODEL=<库里知识库快照的模型名> \
pnpm dev:backend
#   ⚠️ EMBEDDING_API_MODEL 必须与知识库的 embedding_model 快照**同值**（库里存的是 `api:<模型名>`）。
#      不同值**不报错**，只会让检索降级 ⇒ 引用卡一会儿有一会儿没有（那是 P0-1-20 的降级路径，不是本批的 bug）

# ④ 前端照旧
VITE_DEV_PROXY_TARGET=http://127.0.0.1:13000 pnpm dev:frontend   # → http://localhost:5174/
```

> 假上游为什么要用**本仓的**（而不是"随便配个真 Key"）：它刻意带了三个开关 ——
> `thinking: true`（先发一帧 `reasoning_content`，**没有它就没有思考块可看**）、
> `deltaDelayMs`（默认 400ms，真厂商几十毫秒吐完，端测只能看到最后结果 = 什么都没验）、
> `semantic: true`（embedding 侧按字面重叠排序，"含关键词的那块"排第一 ⇒ 才拿得到 `citations`）。
> 它的回答文本是**从请求里抄的**（去 system prompt 的检索块里找「来源：文档名」）⇒「引用卡上的那张卡确实来自检索」变成**可观测差异**，而不是"界面上碰巧有张卡"。
> **想用肉眼盯"思考块展开 → 自动折叠"，把间隔调大**：`UPSTREAM_DELTA_DELAY_MS=1500 pnpm serve:upstreams`。
>
> **⚠️ 这套端测证明什么、不证明什么**（别把"绿的"读成"线上一定对"）：它证明的是**契约与配置接对了** ——
> 事件时序、引用卡的来源、刷新后形态一致、单一渲染路径；**不能**据此推断**真厂商模型**的行为、
> 真实首字延迟或真实产物体积（真模型相关项见 `docs/06` §七 待决事项 2）。

| ㉑ | 新会话态发第一条消息 | **看着回答逐字长出来**（`delta` 逐段追加）；思考块**流式期间默认展开**；`citations` 帧到达时**立刻**出现引用卡（不是等结束才补）；`done` 之后思考块**自动折叠**；**视口自动贴底跟随**（新内容不会被推到视口外） |

| ㉖ | 输入区**五态**（P0-1-33） | 按钮/占位符/提示行三处**同源**于状态机，逐态看：`idle`「发送」可点；`sending`（按下后一小段）按钮禁用、提示「正在发送…」；`streaming`「停止」（**红色**）；`stopping`「停止中…」禁用；`confirm` 提示先处理确认卡（本批无数据源）。右下角 `state: <名>` 的 LED 颜色与状态一致 |
| ㉗ | **停止**（生成中点「停止」） | 走 `POST /:id/stop` → 随后收到 `done{finishReason:'STOPPED'}` ⇒ **已经长出来的内容留在界面上**（不清空）；输入区回到 `idle`，**立刻可以追问** |
| ㉘ | 停止后**马上**追问下一条 | 新的一轮正常开始（**不是** `CONFLICT`）；上一条的已生成内容与它自己的收尾行都在，顺序不乱 |
| ㉙ | **重复发送**（同一会话两处同时发） | 另一标签页/另一窗口在同一会话发消息 ⇒ 失败方收到**专用 toast「该会话正在生成中」**（不是通用错误），且该轮在消息流里留一张**错误卡**；本标签页在 `sending`/`streaming` 期间按钮本就禁用 ⇒ **根本发不出去**（这才是"重复发送"真正被挡住的地方） |
| ㉚ | **断线**（生成中把后端 kill 掉 / 断网） | 流在没有终帧的情况下结束 ⇒ 顶部出现**黄条**「与服务器的连接中断」+ 一行具体线索；已生成的内容**不消失**；**不弹 toast**（客户端侧失败只走黄条 + 错误卡） |
| ㉛ | **点黄条 = 对齐历史** | 黄条整条可点（含键盘 Tab + Enter）；点击后重新拉历史：服务端存了 ⇒ 丢掉本地流式版本（**不会同一轮出现两遍**）、黄条消失；服务端没存 ⇒ 本地那份**保留**（它是唯一副本） |
| ㉜ | 左侧**会话侧栏**（P0-1-34）三态与形态 | 首次加载出骨架；一条会话都没有时出「还没有会话」+ 一句引导（告诉你去右边发第一条）；停掉后端再切走切回 ⇒ 错误态带错误码 + 「重试」。列表按**最近活跃**排序、分「今天 / 更早」两组（**空组不出现**）；每行有状态灯（生成中 / 只读保留 / 可继续，**色 + 字**两重表达）与时间读数；**刚建好还没说过话**的会话显示「还没有消息」（不是拿建会话的时间冒充） |
| ㉝ | 点「+ 新会话」（从一个旧会话里点） | 地址回到 `/chat/:agentId`（**新会话态**，右侧清空并展示开场白）。**再点一次不会再塞一条浏览器历史** ⇒ 按后退能退回刚才那个会话，而不是"后退了却原地不动" |
| ㉞ | 点侧栏里的**另一条**会话 | 右侧换成那条会话的历史（同一套组件）、地址跟着变，侧栏里当前那条有选中态；**按 F5 仍停在这一条**。⚠️ **串台检查（本批新增）**：在 A 会话生成中切到 B —— B 上**不会**看到 A 的增量长出来；B 的输入框会变成「另一个会话正在生成，等它结束再发…」、发送禁用（这是**第六态 `elsewhere`**，不是 bug）；回到 A 仍能看到它继续吐字 |
| ㉟ | 悬停某条 → 点 ✎ **行内重命名** | 出现的是**行内输入框**（不是弹窗）；清空 / 只打空格 ⇒ 「保存」灰着；打 **256** 个字符也灰着、**255** 以内可保存（与后端同一个常量、同样按**码点**算）；按 `Escape` 取消且**不发请求**；**点开又原样保存** ⇒ 不发请求、直接收起（不改 `updatedAt`）；真改名成功 ⇒ 提示「已重命名为「…」」，且**该条不会因此跳到列表最前**（顺序只由"最后一条消息的时刻"决定，改名不算） |

- **会话的"只读保留"状态（状态灯 `warn`）来自"它所属的智能体被软删"**，此时仍可读、不可再生成（`docs/02` §4.4）；
- **工具卡 / 确认卡 / 产物卡 / 排队提示**四样**组件已就位但没有任何数据源**（工具调用与产物属 P0-3，`queued` 的产者是沙箱并发闸）⇒ P0 阶段**永远不会出现**，看到了才是 bug；因此 `confirm` 那个状态**手动点不出来**（它是状态机里的一个分支，无数据源）；
- **`/active` 的进度字段恒为空**：TaskAgent 断线对齐时确实会查一次 `/active`，但 `queuedPosition` / `currentTool` 在 P0 阶段**没有产生方**（沙箱属 P0-3）⇒ 黄条之后不会显示"排队第 N 位 / 当前工具"（**不是漏了**）；
- **只显示最近 20 条**（游标分页默认值），更早的要点消息流顶部的「加载更早的消息」；**没有语法高亮**（与 `docs/03` §一 的"代码高亮"是一处已记录差异，与 `manualChunks` 一起留给 P0-1-36）；
- **窄屏边界**：设计基准 ≥1280px，`<1024` 仅保证可用（对话页在窄屏下侧栏压到 208px、消息流与输入区仍可用；`<720` 时全屏布局不再留底部内边距）；
- **走查完请复位**：把步骤 ② 改掉的 Provider `baseUrl` **改回原值**（或直接删掉那个 Provider），别让它一直指着本机假上游；种子账号若在走查中被改密，按「浏览器端测」首节的复位命令重置。
