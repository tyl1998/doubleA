# 聊天主页与信息架构改造（2026-10-12 立项）

> 上游基准：`01-整体需求与实施步骤.md`、`02-后端设计.md`（§4.5 会话端点）、`03-前端设计.md`（§二 路由表、§三 全局布局、§4.1 对话页）、`子方案/Code模式工作区.md`。
> 定位：把「智能体工作台」的**入口与信息架构**从"先选智能体再进对话"改成"**以聊天为主页**"——进入即看到自己的会话历史，新建对话才选智能体；并把 Code 模式的**列宽/文件显示**从"挤在第三列"改成"对话与工作区可调、可专注"。
> 状态：**设计讨论稿**（2026-10-12 立项定案）。仅此文档 + 一条后端端点（`GET /api/conversations`）与用量权限放宽已落；**前端改造尚未动代码**。落地前需按需求变更流程回写 `03-前端设计.md`。

## 一、问题与目标

### 1. 现状（代码事实，改之前先认清）

| 事实 | 位置 | 后果 |
|------|------|------|
| 首页 = 智能体列表，聊天是**二级页** | `frontend/src/app/App.tsx:72`（`index` = `AgentsListPage`）、`:78`（`/chat/:agentId/:conversationId?`） | 要聊天必须"先选智能体 → 进对话"，不是"进站即聊天" |
| 会话侧栏**只列单个智能体**的会话 | `features/chat/ConversationSidebar.tsx:75`（`useAgentConversations(agentId)`）；后端 `routes/conversations.ts` 的 `GET /api/agents/:id/conversations` | 跨智能体看历史要来回切；**后端无"我的全部会话"端点** |
| 全局导航是一条常驻列（rail），对话页也不例外 | `styles/app.css:35-44`（`.shell` = `rail + 内容`）、`:903-913`（`.chat` = `sidebar + 流 [+ 面板]`）；令牌 `tokens.css:105-106`（`--rail-w:58` / `--rail-open-w:208`） | 聊天主页若再叠"会话历史"列，桌面端会变成 **rail + 会话栏 + 消息流 + 上下文** 四列 |
| Code 模式第三列默认 560px，其中资源管理器**固定 224px** | `features/chat/workspaceModel.ts:319-323`（`WORKSPACE_PANEL_DEFAULT_W=560`）、`styles/app.css:991-999`（`.ws__explorer` 固定 `flex:0 0 224px`） | 编辑器只剩 ~336px，长代码要横向滚；"文件显示大小不符合预期" |
| 文件尺寸**两套口径** | `features/chat/workspaceModel.ts:100`（`formatBytes`，KB/MB/GB）vs `features/chat/ArtifactCard.tsx:65`（`formatSize`，只到 MB） | 同一份字节数在两个页面显示不一致 |
| 文件树**行内不显示 size** | `features/chat/WorkspacePanel.tsx:732-742`（size 只在 `title` 悬停里） | 浏览文件时读不到大小 |
| 会话级开关全挤在标题栏一行 | `pages/chat/ChatPage.tsx:954-1048`（自动审批 / 记忆 / Code / 模型选择 / 编辑 / 产物） | 4~6 个控件与标题争一行，窄屏溢出 |
| 用量统计**仅 ADMIN** | 后端 `routes/usage.ts:22`（`requireAdmin`）；导航 `app/nav.ts:82`（`adminOnly:true`，路由在 `App.tsx:101-105` 的 `RequireAdmin` 内） | 产品口径要改成"登录即可看" |

### 2. 用户原话

> 「现在 agent 模式在对话下前端展示不大符合我的预期，特别是 code 模式，展示的内容文件显示大小不大符合预期……我想着**以用户聊天为主页**。进入后展示的是历史用户的聊天记录，新建对话用户可以从智能体内选择对应的智能体。」
> 「管理分组这里其实也会占用一列对吗……我觉得应该跟着会话走。」
> 「用量的话大家都可以看。」

### 3. 目标与不变量

| # | 不变量 | 含义 |
|---|--------|------|
| I1 | **进站即聊天** | `/` 是聊天主页；选智能体是"新建对话"的一个动作，不是入口前置 |
| I2 | **历史跨智能体** | 左栏一屏看全部会话（带智能体徽标），不再按智能体分栏 |
| I3 | **管理不占聊天列宽** | 管理入口收进会话栏底部，聊天时只有"会话栏 + 对话 (+ 上下文)" |
| I4 | **Code 模式可读** | 编辑器有效宽度有下限；文件尺寸口径统一、行内可见 |
| I5 | **会话归属不变** | 会话仍是私有资源（`conversations.user_id`），跨智能体列表也不破这条 |

**非目标（本设计不做）**：会话在智能体之间迁移、消息搜索/全局检索、多用户协同同一会话、移动端深度重排（只保证可用）。

## 二、新信息架构（路由对照）

| 现在 | 改为 | 说明 |
|------|------|------|
| `/` = 智能体列表 | `/` = **聊天主页** | 左栏会话历史 + 当前会话；无选中时是欢迎态 |
| `/chat/:agentId/:conversationId?` | `/c/:conversationId` | 定位某个会话；`agentId` 由会话数据自带（`conversationItem.agentId/agentName/agentType` 已是快照） |
| — | `/new/:agentId` | 新会话态（展示开场白 + 引导问题，**不建会话**） |

## 三、布局与列数

### 1. 单一外壳（2026-10-13 修订）

> ⚠️ **修订**：首版曾拆成"两种外壳"（聊天主页自带会话栏、管理页走旧的 `.shell + .rail`）。落地后发现
> **点『管理』里的任一功能就跳回旧版 rail 页** —— 两套左侧栏来回换，入口与观感被切成两半。
> 2026-10-13 按**通用 Web 应用（ChatGPT / 飞书一类）**把外壳收敛为**一个**：左列永远是会话栏，
> 只有右列主区随路由换形态。**管理仍然跟会话走**，但不再"进管理页才出现 rail"。

| 路由 | 主区形态 | 列 |
|------|----------|----|
| 聊天视图（`/`、`/c/:id`、`/new/:agentId`、老深链 `/chat/...`） | 消息流 / 欢迎态（自带 `chat__head`，**不叠全局顶栏**） | 2~3 列 |
| 页面视图（智能体/知识库/MCP/任务/产物/凭据/用量/ADMIN 两页） | 顶栏面包屑 + `.page` | 2 列 |

一句话：**一个外壳（`AppShell`）+ 一列常驻会话栏**；聊天与各管理页共用的左侧栏不重挂载、不换样。

| 宽度 | 形态 |

一列承载三件事。~~整栏可收成 56px 图标条~~ ⇒ **R3 修订（§十五）**：收起是**整体隐藏**（不留图标条），

│       每条 = 状态灯 + 标题 + 智能体徽标 + 相对时间
│       行内 hover 浮出 [重命名][删除]（沿用 ConversationSidebar 现状）
│ 底部：▤ 管理 ▸（默认收起，点击弹 popover）

```

管理 popover（不占列宽）：

```
┌─────────────────────┐
│ 智能体   知识库      │
│ MCP      任务        │
│ 会话产物  我的凭据    │

## 六、会话设置收口

> ⚠️ **承载演化（已三次修订）**：标题栏一行 → 齿轮 Popover（首版）→ 标题栏内联（**R3**）→
> **输入框下方图标条（R4，现版）**。R3 把开关从弹层搬回标题栏后，用户在**窄屏 / Code 模式「专注工作区」**
> 下发现标题栏与输入区被挤乱，且希望高频开关用**图标 + 动效**。故 **R4 定案**：
> **标题栏右侧只留「智能体 chip + 设置图标（进编辑智能体）」**；模型 / 自动审批 / 记忆 / Code / 专注 /
> 产物入口全部下沉到**输入框下方**的一排**图标按钮**（`ConversationSettings` 作为 `ChatInput` 的 `controls`）。
> ⚠️ **R5 再修订**：**模型不能只给图标** —— 用户要一眼看到当前模型 ⇒ 模型改回**文字选择器**
> （`Select` / 只读 chip）；其余仍是图标按钮。
> 下表去向以 **R4/R5 为准**（见 §十五 / §十六 / §十七）。

标题栏（`.chat__head`）：**智能体 chip + 设置图标**（~~齿轮 popover~~ / ~~内联文字开关~~）。

会话控件（`.composer__controls`，输入框正下方；图标按钮 + `Tooltip`，点击有 `is-pop` 弹动动效）：

| 项 | 现状位置 | 去向（R4 后） | 约束 |
|----|----------|------|------|
| 模型选择器 | 标题栏 | **输入框下方文字选择器**（`Select`，显示当前模型名；**R5 定案：不再只给图标**） | 池 ≥2 才出现（不变）；未绑定 / 不可用时红 Tag 说明 |
| 自动审批 | 标题栏 | **输入框下方图标**（`SafetyCertificateOutlined`，开=高亮） | 会话级、新会话态可预置（不变） |
| 记忆排除 | 标题栏 | **输入框下方图标**（`BulbOutlined`，记入=高亮） | 会话级；**R3 起新会话态也可预置**（见 §十五） |

| 专注 | 标题栏 | **输入框下方图标**（常规 / 工作区 / 对话） | 仅 Code 模式出现（不变） |

⚠️ 开关的**落点与顺序**不许变（新会话态预置 → `onConversationCreated` 开流前落地），只换承载容器。

## 七、Code 模式布局修正

### 1. 列宽

进入 Code 模式 ⇒ 布局切「窄对话 + 宽工作区」：

```
[会话栏] [对话 360–420px] [工作区 minmax(560px, 1fr)]
```

`ChatPage` 现在用 CSS 变量 `--panel-w` 注入（`ChatPage.tsx:939-943`），改造后：

- 默认工作区宽度从 560 → **640**，下限 420 → **560**（`workspaceModel.ts` 常量）；
- 拖拽夹取区间同步（`clampWorkspacePanelWidth`）。

### 2. 资源管理器可折叠

`.ws__explorer` 由固定 `224px` 支持**折叠成 44px 图标条**（只留文件夹 + 文件图标），把宽度让给编辑器。

### 3. 专注切换

新增「专注工作区 / 专注对话」：

- 专注工作区：消息流收成 360–420px 窄条（或折叠成标题条），工作区占主区；
- 专注对话：工作区收成图标条 / 关闭。

### 4. 尺寸口径与行内显示

- 统一成一个 `formatBytes`（放 `shared/src` 或前端公共 util），删掉 `ArtifactCard.tsx:65` 的 `formatSize`；
- 文件树行内追加尺寸读数（等宽字体，`--font-mono`），与状态栏同口径。

### 5. 宽度记忆

面板宽度与折叠态写入 `localStorage`（键含会话 id 或全局一份；刷新恢复），替代"刷新回默认"。
