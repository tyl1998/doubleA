## 三、交付形态：**两条出口**，不是一条

### 1. 同一个文件的两个用途，安全策略相反

| 用途 | `Content-Disposition` | 其它头 | 谁能触发 |
|------|----------------------|--------|---------|
| **下载**（拿到原文件） | `attachment`（`01` §四 明文要求） | 无 | 产物卡的「下载」 |
| **预览**（在页面里看） | **`inline`** | 见 §四 的响应头表 | 产物卡的「预览」 |

⚠️ **这两条不能合并成"一个端点 + 一个 `?disposition=` 参数"**：那会把**安全策略变成调用方可选的参数**。`attachment` 是"别解释它、存下来"，`inline` 是"当文档渲染它、并且必须带上隔离头"——两者绑定的**隔离强度不同**，由 URL 决定的策略才是可审计的策略。

### 2. ★ 为什么走**后端代理**而不是 MinIO 签名 URL（本文对 `02` §4.8 的修订）

`02` §4.8 原文写的是"时效下载链接（签名 URL，默认 30 分钟）"。**本方案改为后端流式代理**，三条理由，第一条是决定性的：

| # | 理由 | 说明 |
|---|------|------|
| ① | **CSP 只有我方响应头加得上** | HTML 的隔离依赖 `Content-Security-Policy: sandbox`（§六 ①）。签名 URL 的响应由 MinIO 直接发给浏览器，**我们无法给那个响应加任何头** ⇒ 走签名 URL 就必须放弃"直接打开 URL 也安全"这半边，只剩 iframe 属性（可绕过） |
| ② | **S3 端点不必是浏览器可达的** | `S3_ENDPOINT` 现在恰好是 `http://127.0.0.1:19000`（宿主映射），但容器部署形态下它是 `http://minio:9000` ⇒ 要出签名 URL 就得**新增一个 `S3_PUBLIC_ENDPOINT`**（又一个"配错就静默失效"的地址）。代理形态天然没有这个问题 |
| ③ | **不必碰 MinIO 的 CORS** | MD / CSV 要 `fetch` 文本；跨源 fetch 需要 MinIO 配 CORS。代理形态下同源 ⇒ 无需任何 CORS 配置 |

**代价与它的边界**：后端要转发字节（产物单文件上限 50MB，且用户是点开才拉）。⚠️ **不支持 Range**（分段请求）：PDF 会整份下载后显示，跳页不省流量（§八）。

**"时效"没有丢**：两条端点都走 `requireAuth` + 归属校验（产物 → 会话 → 本人），登出即失效 ⇒ 链接**根本不可能被分享给第二个人**（别人点开是 401），安全性高于"拿到链接就能下载 30 分钟"。

### 3. 归属校验（本方案新增的判据）

产物属**会话**、会话属**本人**（`02` §十 的 ④ 族口径：仅本人，**ADMIN 无后门**）。两条端点都必须做：

```
artifact → conversation_id → conversations.user_id === currentUser.id
```

⚠️ 与知识库文档下载端点**刻意不同**：那条是"登录即可"（知识库全员可见）。**照抄它就会漏掉归属校验** —— 症状是"任何登录用户拿着别人的 artifactId 就能下载任意会话的产物"，而两条端点在代码上长得几乎一样。

### 4. ⚠️ 本方案新增**第二个**不套信封的端点

`02` §4.9 记着"下载端点是**全仓唯一**不返回统一信封的端点"。本方案加 `/content` 之后，"唯一"变成"**恰好两个**"，且两者同族：

| 情形 | 响应 |
|------|------|
| 成功 | **字节流**（`reply.send(stream)`），**不套信封** |
| 失败（404 找不到 / 403 不是我的 / 500 取不到对象） | **标准 JSON 信封** |

⇒ 客户端一律**按响应形状（`content-type` 是不是 `application/json`）分支**，不按状态码（P0-1-35 已定案的口径，前端 `api/client.ts#requestBlob` 就是这个）。

## 四、路由与响应头

### 1. 路由表（两条，落 `backend/src/routes/artifacts.ts`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/artifacts/:id/download` | 下载（`attachment`）。**P0-3-9 已定**，本方案只补归属校验与"形态=代理"。✅ **P0-3-9 已落地**（`backend/src/routes/artifacts.ts`：`openArtifactSource()` + 四个响应头 —— 含本方案没写的 `Cache-Control: private, no-store`） |
| GET | `/api/artifacts/:id/content` | **预览（`inline`）**。★ 本方案新增，⏳ **实现属 P0-3-10**（复用 P0-3-9 的 `openArtifactSource()`，只差 §四 2 那组分派头） |

两条共用**一个**取流函数：`openArtifactSource({ userId, artifactId })` → `{ body, contentType, contentLength, fileName }`，与知识库的 `openDocumentSource()` 同族（**先 `statObject` 再 `getObject`**：`getObject` 对不存在的键**不在 `await` 时抛错**，只调它会把 200 头先发出去，症状是"下到一半断了"）。

### 2. 响应头**按 `artifacts.mime` 一处分派**（服务端）

判据函数在 `shared`：`previewKindOf(mime)` → `'html' | 'image' | 'pdf' | 'text' | 'none'`（§五 1）。`/content` 按结果上不同的头：

| `previewKindOf(mime)` | 触发条件 | `Content-Type` | 隔离头 | 其它 |
|------|---------|---------------|--------|------|
| `html` | `text/html`、`application/xhtml+xml`、**`image/svg+xml`** | 原 mime + `; charset=utf-8` | **`Content-Security-Policy: sandbox; default-src 'none'; img-src data:; style-src 'unsafe-inline'`** | `inline` + `nosniff` |
| `image` | 其它 `image/*` | 原 mime | 无（`<img>` 上下文不执行脚本） | `inline` + `nosniff` |
| `pdf` | `application/pdf` | `application/pdf` | **刻意不加 CSP `sandbox`**（§六 ③） | `inline` + `nosniff` |
| `text` | `text/markdown`、`text/csv`、`text/plain`、`application/json`、`text/tab-separated-values` | **`text/plain; charset=utf-8`** | 无 | `inline` + `nosniff` |
| `none` | 其余一切 | `application/octet-stream` | — | `attachment`（当作下载处理） |

**三条要点**（都是"不写就会静默出错"的）：

- ★ **`text` 一律回 `text/plain`**，不回它声明的类型：这样"有人把 `/content` URL 直接贴进地址栏"看到的是**源码**，而不是被浏览器当 HTML 渲染。前端取文本用 `fetch().text()`，与 `Content-Type` 无关。
- ⚠️ **`X-Content-Type-Options: nosniff` 每一路都要有**：缺了它，浏览器可能对 `application/octet-stream` 做内容嗅探，把一份"未知类型"的文件当 HTML 跑起来。
- ⚠️ **`Content-Type` 的唯一来源是 `artifacts.mime`** —— **不是** S3 对象的 `ContentType`、**也不是** `file_name` 的扩展名。原因：前端分派（§五 1）读的就是 `artifacts.mime`，两者必须同源；若响应头取自别处，"界面上是图片、响应头说是 HTML"这种分叉没有任何一层会报错。

## 五、五种格式：渲染与安全处理

### 1. ★ 分派判据只有一处：`shared` 的 `previewKindOf(mime)`

- **前端**用它决定"用哪个渲染器 / 有没有预览入口"；
- **后端**用它决定"上哪一组响应头"（§四 2）。

两个消费者、一个函数 ⇒ 不可能出现"前端当图片渲染、后端却按 HTML 加隔离"的分叉。⚠️ 前端**不得**回头看 `file_name` 的扩展名（`file_name` 是引擎给的，`evil.html` 可以叫 `x.png`；`mime` 才是后端扫描时定的那一个）。

### 2. MD（`text/markdown`）

| 项 | 做法 |
|----|------|
| 取内容 | `fetch('/api/artifacts/:id/content').text()`（体积闸门见 §二） |
| 渲染 | **复用 `features/chat/AssistantMarkdown`** —— `react-markdown` + `remark-gfm`，与助手正文**同一套组件**（`06` §六 第 6 条"单一渲染路径"） |
| 代码高亮 | **不给**（与 `03` §4.4 已记录的差异一致，属 P0-1-36 的事） |

**★ 以下四条是 `react-markdown@10.1.0` 的**实测**行为**（一次性探针实跑，非照抄文档）：

| 输入 | 实测输出 | 结论 |
|------|---------|------|
| `<script>alert(1)</script>` | `&lt;script&gt;alert(1)&lt;/script&gt;` | **raw HTML 被转义为文本**（没装 `rehype-raw` 就不会进 DOM）⇒ 无 XSS 面。**不要**为了让 MD 渲染内嵌 HTML 而加 `rehype-raw` |
| `[x](javascript:alert(3))` | `<a href="">x</a>` | `defaultUrlTransform` 把非法协议**清成空串**（白名单 `https?`/`ircs?`/`mailto`/`xmpp`）⇒ 不可点 |
| `[相对](/api/x)` | 原样保留 | 相对链接会打到**我们后端**（多半 404）—— 属边界，见 §八 |
| `![图](http://evil.example/t.png)` | **原样保留** | ⚠️ **这是唯一的残留风险**：渲染出来浏览器会真的去请求那个外网地址（追踪像素 / 泄露访问者 IP） |

⇒ **对策（前后端两道）**：

1. **前端**：给 `AssistantMarkdown` 传一个 `components.img` 覆盖，把 `src` 过一遍白名单（`data:` + 同源 `/api/...`），**不放行任何跨源地址** —— 跨源图改成"一个可点击的链接 + 占位说明"（用户想看可以自己点，但那是一次有意识的行为，不是静默发生的请求）。
   ⚠️ **不要在产物预览里给整个 SPA 加 CSP `img-src`**：CSP `sandbox` 不支持 `<meta>`（MDN 明文），而给整站加 `img-src` 会把这一个预览的需求扩散成整个应用的约束。
2. **文档**：在 `README` 的端测清单里写明"MD 产物里的外链图片**不会自动加载**"是**预期行为**（否则会被当成 bug）。

### 3. HTML（`text/html`）

```tsx
<iframe
  src={`/api/artifacts/${artifactId}/content`}
  sandbox=""                 // 空 = 最严格：不给 allow-scripts、不给 allow-same-origin
  referrerPolicy="no-referrer"
  title={fileName}
/>
```

- ★ **`sandbox=""` 永远不给 `allow-same-origin`**：给了它，iframe 文档就保留**我们站点的源**，于是它能读 `document.cookie` / `localStorage`（MDN：不带 `allow-same-origin` 时源是 opaque，同源策略检查必然失败）。一份引擎产出的 HTML 不该拥有登录态。
- ★ **`allow-scripts` 不给**：需求 30 的"HTML 预览仅沙箱 iframe"就是这一步。
- **不给 `allow-downloads` / `allow-popups` / `allow-forms`**：默认全关，别顺手加。
- ★★ **iframe 属性是"第二道"，响应头的 CSP `sandbox` 才是"第一道"**：iframe 属性只在**被嵌进 iframe 时**生效；用户在预览弹层里右键"在新标签页打开"、或直接把 `/content` 贴进地址栏，那份文档就**不在 iframe 里**了 —— 此时唯一还在生效的是**响应头**。CSP `sandbox` 对 standalone document 同样生效（MDN 在 `allow-top-navigation` 系列上专门注明"这些值对 standalone document 无效，因为顶层浏览上下文就是它自己"——反过来说明该指令确实作用于 standalone document）。⚠️ 因此 §九 的验收里有一条**专门走"直接打开 URL"这条路径**。
- ⚠️ **CSP `sandbox` 不能写进 `<meta>`**（MDN 明文：本指令不支持 `<meta>`）⇒ 它只可能来自响应头 ⇒ 这也正是 §三 2 ① 的理由。
- ⚠️ **HTML 里的相对资源**（`<img src="chart.png">`）会以 `/api/artifacts/:id/content` 为 base 解析 ⇒ 打到 `/api/artifacts/:id/chart.png` ⇒ 404。P0 **不做资源重写**（§八）。

### 4. 图片（`image/*`，**不含 SVG**）

- `<img src="/api/artifacts/:id/content" loading="lazy" onError={…} />` —— **不 fetch、不进 JS 堆**，交给浏览器。
- 体积闸门 `ARTIFACT_PREVIEW_MAX_INLINE_BYTES`：超过则不给预览入口（只给下载）。
- `onError` 要有兜底文案（会话过期 / 归属不对时是一张 401 的 JSON，img 只会"裂开"；用户看到的是空白而不知道为什么）。
- ★ **`image/svg+xml` 刻意不归这一路**：SVG 是**能带 `<script>` 的文档**。`<img>` 上下文里脚本不执行（安全），但**"在新标签页打开"就会执行**且源是我们的站点 ⇒ 它与 HTML 同级，走 `previewKindOf` 的 `html` 分支（iframe + 双隔离），代价只是"SVG 不在 `<img>` 里直出"，观感完全一样。

### 5. CSV（`text/csv` / `text/tab-separated-values`）

| 项 | 做法 |
|----|------|
| 取内容 | `fetch().text()` |
| 解码 | **UTF-8 严格解码**（`TextDecoder('utf-8', { fatal: true })`）：抛错即**不是 UTF-8** ⇒ 不渲染表格，给一句明确文案（"编码不是 UTF-8，请下载后用本地工具打开"）。⚠️ 别用宽松解码 —— 那会产出满屏 `�` 而用户以为"表里就是这个内容" |
| 分隔符 | **按 mime 定**：`text/tab-separated-values` → `\t`，其余 → `,`。**不做嗅探**（嗅探猜错是静默的，且同一份文件在不同浏览器上可能猜出不同结果） |
| 表头 | **首行当表头**，不给开关（P0 简化；验收场景"汇总表"必然有表头）。⚠️ 这个取舍要写进工具栏文案："首行按表头渲染" |
| 解析器 | **自写纯函数**（RFC 4180：引号包裹、`""` 转义、引号内换行与逗号、CRLF/CR/LF 三种行尾）。⚠️ **不引第三方 CSV 库** —— 它在无依赖验收档里应当是可直接断言的纯函数（§七 2），且"引号内换行"这类分支必须逐条有断言 |
| 渲染 | **AntD `Table` + `virtual`**（5.x 自带），不引新依赖；行高固定、`scroll={{ y }}` |
| 闸门 | 行 / 列 / 单元格三处截断（§二），**截断必须在界面上明示**（"仅显示前 5000 行，共 N 行；下载可看完整文件"） |
| ⚠️ 不做 | **公式注入（`=cmd\|...`）清洗**：我们**不改动产物字节**，只在浏览器里显示文本；把 `=SUM(A1)` 改成 `'=SUM(A1)` 会让"预览"与"下载"看到两份不同的数据（§八） |

### 6. PDF（`application/pdf`）

- `<iframe src="/api/artifacts/:id/content" />` —— 交给浏览器**内置 viewer**。
- ★ **刻意不加 CSP `sandbox`**：MDN 明确说 sandbox "prevents the execution of **plugins**"，而 PDF viewer 属这一类 ⇒ 加了会**渲染不出来**（症状是空框或直接触发下载，看起来像"我们的 PDF 坏了"）。
- 因此 PDF 一路的安全边界**如实写明**：我们**没有**给 PDF 加隔离头，"PDF 内嵌 JS 会不会执行"取决于浏览器内置 viewer 的实现（不是我们的策略）。⚠️ 这是本方案**唯一一处"把安全交给出浏览器"的地方**，写在此处而不是藏在代码注释里。
- ⚠️ 后端代理**不支持 Range** ⇒ 大 PDF 会整份下载后才显示（§三 2 的代价）。

### 7. 其余一切 → 只给下载

`previewKindOf` 返回 `none`（zip、docx、未知类型、空 mime）⇒ 产物卡上**不出现「预览」按钮**（不是置灰），右侧给一句"该格式不支持在线预览"。⚠️ 与 `03` §4.5 的"无编辑权限是灰字不是禁用按钮"同款理由：**能力有无是事实，不是"暂不可用"**。

## 六、★ 六条安全判据（把"每种预览有安全处理"拆成可执行的）

| # | 判据 | 反面（不这么做会怎样） |
|---|------|----------------------|
| ① | **HTML/SVG 的隔离必须落在响应头（CSP `sandbox`），不能只靠 iframe 属性** | 用户在弹层里"在新标签页打开"就绕过了 iframe ⇒ 脚本以**我们的源**执行（能读 cookie） |
| ② | **永远不给 `allow-same-origin`** | 等于把登录态交给引擎产出的文档 |
| ③ | **SVG 归 HTML 那一路，不做 `image/*` 直出** | `<img>` 里安全，但"新标签页打开"执行脚本（一个"看起来只是图片"的文件成了 XSS 面） |
| ④ | **MD 只放行"不外链"的图片** | 追踪像素 / IP 泄露；这是 MD 一路**唯一**的残留风险（实测确认） |
| ⑤ | **`Content-Type` + `nosniff` 由服务端按 `artifacts.mime` 一处决定** | 前端按 mime 渲染、响应头按扩展名 ⇒ 出现"界面上是图片、浏览器当 HTML 跑"的分叉，且**没有任何一层会报错** |
| ⑥ | **预览出口不设 `attachment`** | 把 `01` §四"下载强制 Content-Disposition"照字面套到预览上 ⇒ `<iframe>`/`<img>` 取到的是一份"另存为"的响应，预览全废。**两句话说的是两个出口** |

> ★ 这六条的**取证方式都是"反例"**（§九）：每条都要造一个"不这么做就会出事"的产物去打一次。子方案③ §十二 的定案在这里同样成立 —— **"必然失败"比"成功"更值得验**。

## 七、前端形态

### 1. 弹层与组件落点

- **形态**：AntD `Drawer`（`placement="right"`，宽 `min(1080px, 92vw)`）+ 标题栏（文件名 + 大小 + 「下载」）。与 `03` §4.6"统一为抽屉/全屏弹层，带下载按钮"逐字一致。
- **落点**：`frontend/src/components/ArtifactPreview/`（`03` §六 的 `components/` 里已预留"**预览器**"这个词，本方案把它具体化为这个目录，**不新增结构段**）：

| 文件 | 职责 |
|------|------|
| `ArtifactPreviewDrawer.tsx` | 弹层外壳；按 `previewKindOf` 选渲染器；体积闸门不通过时显示"只给下载"的说明 |
| `MarkdownPreview.tsx` / `HtmlPreview.tsx` / `ImagePreview.tsx` / `CsvPreview.tsx` / `PdfPreview.tsx` | 五个渲染器（各自 ≤ 60 行，安全策略写在各自文件顶部注释里） |
| `artifactPreview.ts` | **零依赖纯逻辑**（不 import React）：CSV 解析、闸门判据、截断读数、下载 URL 构造（§七 2） |

- 产物卡（`features/chat/ArtifactCard`）把 `artifactId` 交给弹层；**URL 由 `artifactPreview.ts` 一处构造**（`/api/artifacts/:id/content` 与 `/download` 各一个函数），不允许各处拼字符串。

### 2. 前端也要有"无依赖纯逻辑档"（照 P0-1-32~35 定制）

`frontend/scripts/verify-artifact-preview.mjs`（`node --import tsx` 直跑源码，**不占端口、不连依赖、不经 vite**）+ 根 `package.json` 两处登记 `verify:artifact-preview`。断言矩阵：

| 组 | 内容 |
|----|------|
| A | `previewKindOf(mime)` 分派矩阵：`text/html`→html、`image/svg+xml`→**html**（★ 不是 image）、`image/png`→image、`application/pdf`→pdf、`text/markdown`→text、`application/octet-stream`/空串/`undefined`→none |
| B | CSV 解析：引号包裹、`""` 转义、**引号内换行**、引号内逗号、CRLF/CR/LF、空行、列数不齐（补空）、TSV 分隔符 |
| C | 三处截断：超行 → 保留 `MAX_ROWS` 且**读数报原始总数**；超列；超长单元格（截断但**原值不改**） |
| D | 体积闸门：`size` 恰好等于上限 ⇒ 放行（边界）；上限 +1 ⇒ 只给下载 |
| E | 下载 / 预览 URL 构造：路径里带上 artifactId、**不带**任何 query |
| F | 源码级守门（扫目录而非 grep 单文件）：`/api/artifacts/` 字符串在 `frontend/src` 下**恰好出现在 `artifactPreview.ts` 一处** |

> 这一档能在**浏览器之前**抓住 C/D 两组 —— 它们是最容易写错、又最难在界面上看出来的两类（"截断读数报的是截断后的数"、"边界写成 `>` 还是 `>=`"）。

## 八、不做 / 边界（写在明处，别当 bug）

| # | 不做的事 | 为什么 | 替代 |
|---|---------|--------|------|
| 1 | HTML 产物里的**相对资源重写** | 要做就得信任"兄弟文件也是同一份产物的合法分片"，并引入一层路径改写（新的注入面） | 产物自带内联或绝对地址；失败时用户下载原文件看 |
| 2 | **Range / 断点续传** | 需要流式透传 Range 头与 206 响应，且与"先 stat 再取"的既有形态要重新对齐 | 大 PDF 整份下载后显示；产物单文件 ≤ 50MB |
| 3 | **编码嗅探**（GBK 等） | 猜错是静默的（满屏 `�` 而用户以为文件就是这样） | 严格 UTF-8 解码失败 ⇒ 明确提示 + 下载 |
| 4 | **CSV 公式注入清洗** | 会让"预览"与"下载"看到两份不同的数据 | 不改产物字节；若将来做**导出**再在导出侧处理 |
| 5 | MD **代码高亮** | 与 `03` §4.4 已记录的差异一致（体积） | P0-1-36 定；只需接在 `AssistantMarkdown` 一处 |
| 6 | 产物列表**缩略图** | 需求没有；会给扫描/上传路径加一条图像处理支线 | — |
| 7 | 非 UTF-8 的 **HTML 产物** | 我们强制 `charset=utf-8` ⇒ 声明 GBK 的产物会乱码 | 同上第 3 条 |
| 8 | **多实例部署** | 与本方案无关（代理端点是**无状态**的）：产物与 SSE 流不同 —— 后者有单实例限制（子方案③ §八 2） | — |

## 九、验收清单（对应 `01` 需求 30 的"预览"半边）

| 验收点 | 取证方式 |
|--------|---------|
| 五种格式各有预览形态（MD/HTML/图片/CSV/PDF） | 浏览器端测（P0-3-11 后）：逐格式点一次 |
| 下载端点仍强 `attachment` 且文件名正确（含中文） | 浏览器 + `curl -D-` |
| **归属校验**：拿**别人的** artifactId 打两条端点 ⇒ 403/404 | 命令行（**必须用非创建者账号**，`06` §六 第 3 条） |
| ★ **HTML 产物直接打开 `/content`（不经 iframe）也不执行脚本** | 新标签页打开该 URL，页面**不含**被执行的证据（弹窗/`console` 无输出） |
| ★ **MD 产物里的 `<script>` 显示为字面文本** | 浏览器端测，看渲染结果 |
| ★ **MD 产物里的外链图片不发起请求** | DevTools Network：无该地址 |
| ★ **MD 产物里的 `javascript:` 链接不可点** | 浏览器端测 |
| **SVG 产物走 iframe 而非 `<img>`** | 浏览器端测 + 源码级断言（§七 2 A 组） |
| **CSV 超 5000 行** ⇒ 表格截断且读数报原始总数 | 造一份 6000 行的 CSV 产物 |
| **非 UTF-8 的 CSV** ⇒ 明确提示而不是满屏 `�` | 造一份 GBK 的 CSV 产物 |
| **超大产物**（> 10 MiB 图片）⇒ 无预览入口、只有下载 | 造一份 12MB 的 PNG |
| `none` 类型（zip）⇒ **没有**「预览」按钮 | 浏览器端测 |
| 无依赖档 A~F 六组全绿 | `pnpm verify:artifact-preview`（**人工执行**） |

> ⚠️ 本仓验收用的是**本仓夹具产物**（含故意构造的恶意产物）⇒ 它证明的是"**我们对这五类内容的处理是对的**"，
> **不是**"真实引擎产出的文件都长这样"。真产物相关的项见 §十。
