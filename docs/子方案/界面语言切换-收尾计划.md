### 目标形状

`sandboxBuildJobSchema` **增 `detail`**、把 `phaseLabel` **降级为可选并标 `@deprecated`**（不直接删）：

```ts
/** 当前阶段的**细节**（组件名 / RUN 概要；没有时为 null）。由前端与 `phase` 组合成一句人话 */
detail: z.string().nullable(),
/** @deprecated 后端不再更新；仅为兼容旧前端保留（将随下个版本删除） */
phaseLabel: z.string().optional(),
```

理由：一次性删 `phaseLabel` 会让"新后端 + 旧前端"（常见于灰度）拿到 `undefined` —— 那一行变成空白。
保留但停止更新 = 旧前端退化成"只显示阶段名"，不会崩。

## 附录：不能用「模板 key」硬套的 6 条（做 ② 时怎么处理）

这几条是**跨字段 / 跨实体**的语义，不是"某个字段超长了"，所以**不要**塞进 `validation.maxLength` 这种模板。
但它们**仍然是 `data.fields[].message`**（zod 的消息只能走这条路），所以也**不给它们新增错误码** ——
那要改 `ERROR_CODES` 与后端的错误映射，属于另一件事。做法是**整句 key**（不带参数或只带一个标识）：

| 消息（原文，zh 逐字保留） | 所在 | 处理 |
|---|---|---|
| `同一条绑定重复提交了` | `agent.ts` | 整句 key `validation.agent.duplicateBinding`（重复项索引前端自己算不出，也不打算给） |
| `默认模型必须在模型池中` | `agent.ts` | 整句 key `validation.agent.defaultModelNotInPool`（不需要 `{modelId}`：字段本身就是那个下拉） |
| `可见范围为「指定用户」时，至少要选择一位用户或一个组` | `agent.ts` / `knowledgeBase.ts` | **两处共用**一条 `validation.audience.required` |
| `只有可见范围为「指定用户」时才能设置受众` | 同上 | `validation.audience.notAllowed` |
| `标题模型必须是对话模型` | `titleModel.ts` | `validation.titleModel.mustBeChat` |
| `源路径与目标路径相同` | `workspace.ts` | `validation.workspace.samePath` |

> 判据：**能参数化的才参数化**（`{max}` / `{allowed}` / `{name}`），**不能的就整句**。
> 两种情况都是 key；区别只在于字典里那条有没有占位符。
> 真要走独立错误码的，是 `service` 层抛的 `AppError`（不走 zod），按 `02` §四 的增量约定办 ——
> 那批不在 ② 的范围里。
