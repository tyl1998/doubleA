## 一、缘起：为什么改成「Agent 是唯一共享单位」

这一版不是给 ⑥ 打补丁，而是**换掉它的可见性模型**。推导链（每一步都是上一轮讨论里暴露出来的真问题）：

1. **模型池 Provider 的可见性没有意义。** 模型**只能通过某个 Agent 被使用**（`createConversation` 必须带 `agentId`），没有"直接调用模型"的路径。所以 Provider 的 `PUBLIC/PRIVATE` 既不承担访问控制（那归 **Agent 可见性**），又制造"公开 = 别人用我的 Key"的歧义。
2. **"非 ADMIN 不得公开自有 Provider"这条禁令自相矛盾。** 它的理由是"公开 = 别人烧你的 Key 额度"，可一旦引入**用户自带 Key**（P1-13 增量），这个前提就不成立了。⇒ 该禁令随 Provider 可见性一起**取消**。
3. **Provider 的"定向分享"也随之无用。** 分享的目的是"让别人用我的模型"，但模型只能经 Agent 用 —— 让某人用我的模型，正确的做法是**分享/公开那个 Agent**，不是分享 Provider。⇒ 删除 `provider_shares`。
4. **给 Agent/KB 各加一道可见性闸，就冒出"闭包"这个死结。** 组件（KB/MCP）是**通过 Agent 被用**的，却要**独立**判可见性 ⇒ "公开 Agent 能不能引用私有 KB"没有好答案（引用私有则分享者看不到、要求公开则把私有 KB 泄漏给所有人）。
5. **结论：授权应当跟着「使用路径」走，而不是给每个资产各设一道闸。** 组件是通过 Agent 被用的 ⇒ **"谁能用这个 Agent"就决定了"谁能用它的组件"**。这正是第 1 步对 Provider 已经采用的同一条原则（"模型访问随 Agent"），把它**统一**到 KB/MCP 上，闭包就不需要存在了。
6. **"指定用户"只保留在 Agent 上**（唯一真正需要"只给某些人"的共享单位）；KB/MCP 用最粗的两档表达"愿不愿意放进公共池让别人独立复用"。
7. 用户追加：**受众圈选要支持"组 / 标签"** —— 选"指定用户"时，能按**某个组**或**某个标签**下的人来授权，而不是只能一个个点人。

## 三、可见范围模型（重设计）

### 3.1 枚举

`AssetVisibility = { PRIVATE, SHARED, PUBLIC }`（迁移 `20261016120000_asset_acl` 的 `CREATE TYPE` 直接含 `SHARED`）。

| 档位 | 含义 | 适用资产 |
|------|------|----------|
| `PRIVATE`（私有） | 仅**所属人**（+ ADMIN） | Agent / 知识库 / MCP |
| `SHARED`（指定用户） | 所属人 + **受众**（用户/组/标签圈定的人）+ ADMIN | **仅 Agent** |
| `PUBLIC`（公开） | 全部登录用户（+ ADMIN） | Agent / 知识库 / MCP |

> Provider **不在**此表：它没有可见范围（**读 = 全体登录用户**，即"平台模型池"人人可见、只读；
> **写 = 所属人 + ADMIN**）。

### 3.2 权限矩阵（唯一判据 = `shared/src/assetAcl.ts`）

| 操作 | 所属人 | ADMIN | 其它登录用户 |
|------|--------|-------|-------------|
| 看/列表可见（Agent/KB/MCP） | 自己的全部（含私有） | 全部 | `PUBLIC`；`SHARED` 且在受众内 |
| 用（对话用 Agent；把 KB/MCP 绑到**自己的** Agent；KB 直接检索） | 自己的全部 | 全部 | `PUBLIC`；`SHARED` 且在受众内 |
| **经某个我能用的 Agent 使用其组件/模型** | 允许 | 允许 | **允许**（授权来自该 Agent 的受众，不看组件自身可见范围） |
| 编 / 删 / 改可见范围 / 转移 | 自己的 | 全部 | 禁止（403） |
| 看 Provider（含其模型） | 全部 | 全部 | 全部（平台模型池人人可见、只读） |
| 编 / 删 / 转移 Provider（含建模型） | 自己的 | 全部 | 禁止（403） |

- **私有资产对他人 = 404**（不泄漏存在性）；**存在但无编删权 = 403**。
- **ADMIN 对资产全权**（与"凭据无后门"不同族）—— 资产是协作对象。

### 3.3 组件与 Agent 的关系（取代闭包）

- Agent 的**组件**（KB/MCP）与**模型池**在**被该 Agent 使用**时，**不**受组件/Provider 自身可见范围的约束 —— 授权来自 Agent 的受众（定案 5）。
- 因此**没有写时闭包**：把 Agent 改成 `PUBLIC`/`SHARED` 不再校验引用（定案 4）。
- **想收回某个组件**：从 Agent **解绑**（而不是去改组件可见范围）。
- **提示**（定案 6）：把 Agent 设为 `PUBLIC`/`SHARED` 时，前端提示"其引用的私有知识库/工具内容、以及共享 Key 的模型额度，将对该受众可见/可用"。

## 四、受众（用户 / 组 / 标签）

### 4.1 语义

`指定用户` 的**受众** = 若干**受众主体**的**并集**：

```
受众(agent) = 直接指定的用户 ∪ ⋃(指定组的成员) ∪ ⋃(打了指定标签的用户)
```

`canViewAsset(agent, viewer)` 在 `SHARED` 时判：`viewer` 是否落在上面这个并集里（ADMIN / 所属人始终通过）。

### 4.2 三类主体

| 主体 | 定义 | 维护者 | 定位 |
|------|------|--------|------|
| `USER` | 单个用户 | —— | 精确到人 |
| `GROUP`（组） | **显式成员集合**（有名字、有成员表） | **ADMIN**（推荐） | **主授权单位**：稳定、可审计、语义清晰 |
| `TAG`（标签） | 附着在**用户**上的标签（一人可多标签） | 待决（ADMIN / 用户自打） | 灵活圈选（如"测试""研发"） |

> **推荐先做「组」**：授权对象应稳定可审计，组的成员由 ADMIN 显式维护；标签更偏"分类/筛选"，作为后续增量（见 §九 待决 1）。

### 4.3 解析成本（要点）

- **单条判权**：解析 viewer 的组集合 / 标签集合（各 1 次查询），再判"是否命中受众"。
- **列表过滤**（`GET /api/agents`）：先解析 viewer 的 `groupIds`/`tagIds`，再拼 Prisma `where`：

  ```
  { OR: [
      { visibility: 'PUBLIC' },
      { createdBy: viewer.id },
      { visibility: 'SHARED', audiences: { some: { subjectType: 'USER',  subjectId: viewer.id } } },
      { visibility: 'SHARED', audiences: { some: { subjectType: 'GROUP', subjectId: { in: myGroupIds } } } },
      { visibility: 'SHARED', audiences: { some: { subjectType: 'TAG',   subjectId: { in: myTagIds } } } },
  ] }
  ```

  ⇒ 每次 Agent 列表多 1~2 次小查询（解析组/标签）；规模可控。

## 十、P1-18 · Provider 用户级凭据（私人 Key；本批的子批 C）

**模型 Provider 用户级凭据（每人自带 Key）** —— 用户 2026-10-16 提出，**归属 P1-18**（Provider 子批）：

- Provider 加 `credentialMode ∈ {SHARED, PER_USER}`（共享 Key / 各自 Key）+ 新表 `provider_user_credentials`（`(provider_id, user_id)`，AES-256-GCM，**AAD 含 `user:provider`**，与 `providerKeyAad` 分开）。
- `resolveChatTarget`/`readProviderCredential` 增加"凭据主语"：`SHARED` 取 Provider Key；`PER_USER` 取**调用者**的 Key，缺 ⇒ **424 `NEED_CREDENTIAL`**。
- 与"可见范围"**正交**：可见范围管"谁能用"，凭据模式管"用谁的 Key"。
- 前端：Provider 表单加"凭据模式"；`PER_USER` 时加"我的 Key"入口；`NEED_CREDENTIAL` 走既有 424 提示通道。
- **注意**：有了 `PER_USER` 后，Provider 若将来需要"公开"也不再烧所属人额度 —— 但本批**仍不给 Provider 可见范围**（模型只能通过 Agent 用，见 §一）。
