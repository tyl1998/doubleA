# 子方案⑥ — 资产所属人与权限控制

> 上游基准：`01-整体需求与实施步骤.md`（决策 18、22、21；本方案新增决策 29/30/31）、`02-后端设计.md`（§三 数据模型、§四 API、§4.3 模型池、§4.4 Agent、§4.6 知识库、§4.7 MCP）、`03-前端设计.md`（§二 路由与页面清单、§4.x 各页形态）、`05-P系列计划拆分.md`（§三 P1-13）。
> 定位：给平台里的**可复用资产**（Agent / 知识库 / MCP Server / 模型池 Provider）补上**统一的「所属人 + 可见性 + 权限」**模型，并把**模型池的创建放开**给全员。
> ⚠️ 本方案是对既有口径的**一次系统性修订**（收尾时按需求变更流程回写 `01`/`02`/`03`/`05`/`06`）：原「Agent = 创建者 + ADMIN、知识库 = 全员、MCP = 注册者 + ADMIN」三套**互不一致**的口径，统一为**一套**。
> 状态：🚧 **P1-13 已落地（2026-10-16）**（所属人 / 转移 / 模型池放宽为登录 + 行级 CRUD / 可见性初版）；⚠️ **其中「可见性 / 权限矩阵 / 可见性闭包」部分已被 `子方案⑧` 取代**（2026-10-16，见文件头两段修订），后续归 **P1-18**。原"6 条待决"已按推荐默认值拍板完毕。

> ## ⚠️ 施工后修订（2026-10-16，用户定案；P1-13 已落地）
> **模型池 Provider 移除可见性**（四类资产里仅 **Agent / 知识库 / MCP Server** 保留 `PUBLIC`/`PRIVATE`）。
> **原因**：模型只能通过某个 **Agent** 被使用 ⇒ Provider 的全局"曝光"（1）不承担访问控制（那归 **Agent 可见性**）、
> （2）制造"公开 = 用谁的 Key"的歧义（与本方案 §四"非 ADMIN 不得公开自有 Provider"的理由**自相矛盾**）、
> （3）还要为它维护可见性闭包与前端开关，"也不好管理"。
> **修订后的 Provider 口径**：
> · 访问（列表可见 / 可编删 / 可被绑定） = **所属人 + ADMIN + `provider_shares` 被分享者**（**没有**全局公开）；
> · 定向分享是**唯一**的"授权他人复用"入口（只读：可看/可用其模型，不可编删）；
> · 可见性闭包**只剩 Agent 的 KB/MCP 组件**（不再含模型池 Provider）；
> · **公开 Agent 引用共享 Key 的 Provider = 所属人自愿共享 Key 额度，仅提示不拦**（§八 决策 ② 随之失效 —— 没有公开可言）。
> 本文以下 §二 / §三 / §四 中凡提到"Provider 的 `visibility` / 公开 / 非 ADMIN 不得公开"的部分，**以本修订为准**（保留原文以见演进）。
>
> ## ⚠️ 进一步修订（2026-10-16）：可见性模型**整体被 `子方案⑧` 取代**（批次 **P1-18**）
> 本轮讨论后定案**换掉本文的可见性模型**（详见 **`子方案/资产共享与用户组标签.md`（⑧）** 与 `01` 决策 37；**批次号 = P1-18**）：
> · **Provider**：无可见范围 + **删除定向分享**（本文 §四 的 Provider 公开/分享**作废**）；
> · **Agent**：三档 `私有 / 指定用户 / 公开`（**唯一**带 per-user 受众）；**知识库 / MCP**：两档 `私有 / 公开`；
> · **可见性闭包取消**（本文 §3.4 与 `01` 决策 31 **作废**）：组件通过 Agent 被使用时，授权来自 **Agent 的受众**，与组件自身可见范围无关；运行时**不再按可见性过滤组件**；
> · 公开/指定用户 Agent 引用私有组件或共享 Key 的 Provider = **自愿共享，仅提示不拦**；
> · 受众支持 **用户 / 组 / 标签**；新增登录可用的用户搜索端点。
> **本文仍然有效**的部分：**所属人（决策 29）**、**转移所属人**、**模型池由 ADMIN-only 放宽为登录 + 行级**、四类资产一起上线。

## 一、问题（现状盘点）

### 1.1 两张现状表

**资产表**（本次纳入范围的四个实体）：

| 资产 | 现有归属列 | 现有权限口径（出处） | 可见性 | 转移 |
|------|-----------|---------------------|--------|------|
| Agent | `agents.created_by` | 全员可建可看可用；创建者 + ADMIN 编删（`01` 决策 18） | 无（等同全员可见） | 无 |
| 知识库 | **无** | 登录即可增删改查**任意**库（`02` §4.6；`routes/knowledgeBases.ts` 自认口径缺口） | 无 | 无 |
| MCP Server | `mcp_servers.created_by`（= 注册者/所属人） | 全员可建可看；**改/删 = 注册者 + ADMIN**（`01` 决策 22，P0-2-12 定案） | 无 | 无（schema 注明「转移属 P1」，但从未排期） |
| Provider / Model | **无** | **仅 ADMIN** 可建可管；全员可选用（`01` 决策 9） | 无 | 无 |

**非资产（本次不纳入，继续"仅本人"）**：会话（`conversations.user_id`）、文件（`files.uploader_id`）、产物（`artifacts.user_id`）、定时任务（`scheduled_tasks.user_id`）、MCP 凭据（`mcp_credentials.user_id`）、沙箱（`sandboxes.user_id`）。它们的判据是"这一行是不是你的"，本方案**不引入"公开"**（用户 2026-10-10 定案：资产范围 = Agent / 知识库 / MCP Server，另加模型池 Provider）。

### 1.2 两个缺口

1. **所属人（owner）缺失**：知识库与模型池**根本没有**归属列；Agent/MCP 有 `created_by`，但**没有转移入口**（创建者一旦离职/换岗，资产就锁死）。
2. **权限控制不成体系**：整个设计**没有"可见性（公开/私有）"这一维度**，规则按实体各写各的（Agent = 创建者+ADMIN、KB = 全员、MCP = 注册者+ADMIN、Provider = ADMIN），既不一致、也无法表达"我建的东西只想给自己用"。

本方案给出**一套**模型同时解决这两点。

## 二、术语与范围

| 术语 | 定义 |
|------|------|
| **资产** | Agent、知识库（KnowledgeBase）、MCP Server、模型池 Provider（其下 Model 随 Provider）。 |
| **所属人**（owner） | 资产的责任人，**权限判据的唯一主体**。初值 = 创建者，可经「转移」变更。 |
| **可见性**（visibility） | `PUBLIC`（公开）/ `PRIVATE`（私有）。公开 = 全部登录用户可**看**可**用**；私有 = 仅所属人（+ ADMIN）可看可用。 |
| **ADMIN** | 平台管理员（`users.role = ADMIN`）。对**全部**资产有**全部**权限（看/用/编/删/改可见性/转移）—— 资产层的"后门"是**刻意保留**的（与 `mcp_credentials` 的"ADMIN 也无后门"**不同族**：凭据是个人隐私，资产是协作对象）。 |
| **创建者** | 首次创建该资产的人。**是否单独留痕**见 §八 待决 1。 |

**不在范围**：会话、文件、产物、定时任务、MCP 凭据、沙箱；以及权限的"共享/授权给指定用户"（用户 2026-10-10 定案：本次只到"所属人 + ADMIN + 公开/私有"，**不加资源级 ACL**）。

## 三、统一模型

### 3.1 所属人（owner）

四张资产表**各有一列**作为权限主体：

- Agent / MCP Server：**复用现有 `created_by`**（语义由"创建者"扩为"所属人"，初值 = 创建者；转移时更新该列）。
- 知识库 / Provider：**新增** `created_by uuid NOT NULL`（回填见 §五）。
- ⚠️ **本方案有两版列命名，见 §八 待决 1** ——
  - **方案甲（本方案默认，低改动）**：继续叫 `created_by`，语义扩为"所属人"（README/`02` 里一句话把"创建者"改称"所属人/创建者"）。
  - **方案乙（更干净，改动大）**：四表统一改名 `owner_id`，`created_by` 一律不保留（新表的"谁建的"交给审计日志）。
  - 选甲的理由：`created_by` 在 `shared/src/mcp.ts#canEditMcpServer`、`agent.service.ts`、前端多处已有契约，改名会波及 SSE/类型/前端；且 MCP 文档早已把它当"所属人"用。

**约束**：`owner_id`/`created_by` 外键 `onDelete: Restrict`（沿用现状）；只允许指向 `status = ACTIVE` 的用户（服务层校验，转移时）。

### 3.2 可见性（visibility）

新增枚举 + 列（四张资产表各一列；`models` 除外——见下）：

```
enum AssetVisibility { PUBLIC, PRIVATE }
```

| 落点 | 说明 |
|------|------|
| `agents.visibility` | 默认 `PRIVATE`；存量行回填 `PUBLIC`（保持现有"全员可见"） |
| `knowledge_bases.visibility` | 同上 |
| `mcp_servers.visibility` | 同上 |
| `model_providers.visibility` | 默认 `PRIVATE`；**存量行回填 `PUBLIC`**（= 现全员可选用）；**ADMIN 新建默认 `PUBLIC`（= 系统级）**，非 ADMIN 新建默认 `PRIVATE` |
| `models.visibility` | **不加**：Model 随 Provider 可见（模型离开 Provider 无意义）。判据统一取 `provider.visibility` |

- **可见性只有两值**，没有"团队/部门"。`01` 现状里"全员可见"直接映射为 `PUBLIC`。
- **默认值取 `PRIVATE` 是安全默认**：新资产先归自己，确认要协作再手动公开。
- **系统级模型 = `owner=ADMIN` 且 `visibility=PUBLIC`**（用户 2026-10-10 表述的"admin 创建默认为系统级别"）。

### 3.3 权限矩阵（唯一判据）

| 操作 | 所属人 | ADMIN | 其它登录用户 |
|------|--------|-------|-------------|
| 看 / 列表可见 | 自己的全部（含私有） | 全部 | 仅 `PUBLIC` |
| 用（对话、被绑定、被检索、被选作 embedding/caption 模型） | 自己的全部 | 全部 | 仅 `PUBLIC` |
| 编（改名/改内容/组件绑定/检索配置…） | 自己的 | 全部 | 禁止（403） |
| 删 | 自己的 | 全部 | 禁止（403） |
| 改可见性（公开/转私有） | 自己的 | 全部 | 禁止 |
| 转移所属人 | 自己的 | 全部 | 禁止 |

- **"看/用"对私有资产 = 404**（不泄漏存在性），对"存在但无编删权" = **403**，与现有 `mcpServer.service.ts` 的"先 404 再 403"同款。
- 判据**只有一处来源**：`shared/src/assetAcl.ts`（新），导出 `canViewAsset` / `canEditAsset` / `canTransferAsset` —— 后端路由、服务层、前端（拿到 `ownerId`/`visibility` 后各自算按钮显隐）**都读它**，不允许各写一份（`06` §六 的"唯一来源"纪律）。

### 3.4 可见性闭包（跨资产引用的硬约束）

资产之间会互相引用：Agent 绑 KB/MCP、Agent 的模型池、KB 的 embedding/caption 模型。**公开的东西不能把私有的内容漏出去**：

1. **私有资产**：只能引用**对自己可见**的资产（自己的私有 + 任何公开）。
2. **公开资产**：只能引用**公开**资产。
   - **写时强制**：把一个资产**改为 `PUBLIC`**（或创建即公开）时，校验其全部引用；有任一引用是私有 ⇒ **拒绝**（HTTP 422），响应列出**需先公开的引用清单**（例："该智能体绑定了私有知识库《X》，请先将其公开或解绑"）。
   - **绑定时校验**：绑定组件时只能选"对自己可见"的，天然满足。
3. **运行时兜底**（防御性）：装配给某用户的资产时，**再按该用户可见性过滤一次**组件（防历史数据/并发下的漏网，也防"先建公开、事后把组件改私有"的时序缝）。
4. **反向**：把一个资产**从公开改为私有**是**允许**的（收窄无害）；此后它引用的公开资产不受影响。

> 这条规则替代现有"知识库全员可见"的口径：以后只有**公开**知识库才全员可检索。

### 3.5 转移所属人

- 端点：`POST /api/{asset}/:id/transfer`，body `{ toUserId }`（或 `PATCH` 带 `ownerId`，见 §八 待决 3）。
- 权限：仅**所属人或 ADMIN**。
- 校验：`toUserId` 必须是 `ACTIVE` 用户；不能转给自己。
- 效果：`created_by`/`owner_id` 改为新所属人；此后权限随新所属人。
- ⚠️ **MCP 特例**：`mcp_servers.created_by` 同时是**探测主语**（`POST /:id/test` 与 `GET /:id/tools` 用**注册者**的凭据连上游，`tool_cache` 是 server 级共享的）。转移后探测主语变为新所属人 —— 若新所属人**没配该 server 的凭据**，测试/工具列表会失败（调用 `tools/call` 仍用**调用者自己**的凭据，不受影响）。**前端转移弹窗必须就此给出提示**（沿用 `01` 决策 22 的口径）。

## 四、模型池开放在内的具体口径

现状：`/api/providers`、`/api/models` **仅 ADMIN**（`01` 决策 9）。本次放开：

| 项 | 变更 |
|----|------|
| 创建 | **登录即可**创建 Provider / Model；创建者成为所属人 |
| 默认可见性 | ADMIN 建 `PUBLIC`（系统级）；非 ADMIN 建 `PRIVATE` |
| 列表 `GET` | 返回"对我可见"的：`PUBLIC` + 自己的 `PRIVATE`（ADMIN 见全部）。**停用（`enabled=false`）的仍筛掉**（`01` §3.2） |
| 编/删 | 所属人或 ADMIN（行级）。⚠️ **系统级 Provider（owner=ADMIN 且 PUBLIC）只有 ADMIN 能改/删**（防普通用户改坏系统模型） |
| 选用 | Agent 的模型池、KB 的 embedding/caption 模型**只能从"对我可见"的模型里选**（§3.4 闭包） |
| Key 安全 | `api_key_enc` 仍**服务端加密、永不回显**（不变）；⚠️ 公开一个 Provider = 他人可**用这个 Key 消费额度** ⇒ **非 ADMIN 禁止把自己的 Provider 设为 `PUBLIC`**（见 §八 待决 2） |

> 页面：`/admin/models` 由"仅 ADMIN"改为"登录可见"的**模型池页**（普通用户只看/管自己的）； ADMIN 在同一页看到全部。路由与导航的改造见 §七。

## 六、API 变更

### 6.1 契约增量（所有资产通用）

每张资产的 **create body / update body** 增加可选 `visibility`（默认 `PRIVATE`；ADMIN 建 Provider 默认 `PUBLIC`）；**item / detail 响应**增加 `ownerId`、`ownerName`、`visibility`、`canEdit`（由后端按 `canEditAsset` 算好，前端不自己拼 —— 与 `mcpServer.service.ts` 的"别把 `createdBy === 我` 挪到前端去算"同款）。

### 6.2 新增端点

| 端点 | 权限 | 说明 |
|------|------|------|
| `POST /api/agents/:id/transfer` | 所属人 / ADMIN | `{ toUserId }` |
| `POST /api/knowledge-bases/:id/transfer` | 所属人 / ADMIN | 同上 |
| `POST /api/mcp/servers/:id/transfer` | 所属人 / ADMIN | 同上；响应带探测主语变更提示 |
| `POST /api/providers/:id/transfer` | 所属人 / ADMIN | 同上 |

### 6.3 既有端点变更

| 端点 | 变更 |
|------|------|
| `GET /api/knowledge-bases`、`GET /api/agents`、`GET /api/mcp/servers` | 列表按"对我可见"过滤（`PUBLIC` + 自己）；可加 `?scope=mine` 只看自己的 |
| `GET/POST/PATCH/DELETE /api/providers`、`/api/models` | 由 ADMIN-only 放宽为"登录 + 行级"（§四） |
| `PUT /api/agents/:id/components` | 绑定时校验"组件对我可见"；若 Agent 是 `PUBLIC` 则组件必须 `PUBLIC`（§3.4） |
| `PATCH /api/agents/:id`、`PATCH /api/knowledge-bases/:id` … | 改 `visibility` 为 `PUBLIC` 时跑闭包校验（§3.4），失败 422 + 清单 |
| 对话/检索装配 | 运行时按可见性过滤组件（§3.4 第 3 条） |

| 3 | **转移是否需要接收方确认** | 影响端点形状与状态机 | **不需要**（属主/ADMIN 单方动作即可），后续如需再加"待接受"态 | 🟡 待用户确认 |
| 4 | **知识库/Provider 存量行的 owner 回填给谁** | 影响老资产的归属 | 回填给**最早的 ADMIN**（可作为系统资产）；`visibility` 一律 `PUBLIC` 保行为不变 | 🟡 待用户确认 |
| 5 | **停用用户（无硬删）的私有资产** | 其 `PRIVATE` 资产将只剩 ADMIN 可见可管 | 沿用（不自动转移）；如需转移由 ADMIN 手工做 | 已定（沿用现状） |
| 6 | **公开 Agent 引用私有组件** | 内容泄漏风险 | **写时拒绝 + 运行时过滤**（§3.4） | 已定 |

## 九、验收判据

**权限矩阵正反用例**（每条资产都过一遍）：

1. MEMBER A 建 Agent（默认私有）→ A 能看/编/删；B **看不到**（列表无、直连 404）；ADMIN 能看/编/删。
2. A 把 Agent 改公开 → B 能看到、能对话；B **不能**编/删（403）。
3. A 把 Agent 改公开但其绑定了 A 的私有 KB ⇒ **422 + 引用清单**；A 先公开 KB 后再公开 Agent 成功。
4. 公开 Agent + A 把其私有 KB 事后改回私有 ⇒ 他人对话**不再命中该 KB**（运行时过滤）。
5. A 转移 Agent 给 B（`toUserId=B`）⇒ B 成为所属人可编删；A 失去编删权。
6. 非 ADMIN C 建 Provider（默认私有）⇒ C 能建 Agent 用它；A/B **看不到**该 Provider（`GET /api/models` 不含）。
7. ADMIN 建 Provider ⇒ `PUBLIC`（系统级），全员可见可用；C **不能**改/删它（403）。
8. 知识库：A 建库（默认私有）⇒ B 看不到；公开后 B 可用；转移给 B 后 B 可编删。

**取数口径**：真跑取证（两个 MEMBER + 一个 ADMIN 账号，覆盖上表 8 组）留给用户（`06` §六 第 30 条）；智能体自证只到 `typecheck`/`eslint`/`check:batch` + 新增 `verify:asset-acl` 脚本。
