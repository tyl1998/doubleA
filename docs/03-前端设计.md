# 内部 Agent 工作台 — 前端设计

> 配套：`01-整体需求与实施步骤.md`、`02-后端设计.md`（SSE 契约以 02 第五节为准）。
> 技术结论：React + TypeScript，与后端同仓 monorepo 共享类型。自包含设计。

---

## 一、技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | React 18 + Vite + TypeScript | 轻、快、无重脚手架 |
| UI 库 | Ant Design 5 | 表格/表单/弹窗全齐，内部工具效率优先 |
| 路由 | React Router 6 | — |
| 服务端状态 | TanStack Query | 列表/详情的缓存、失效、重试 |
| 客户端状态 | Zustand | 轻量；SSE 流式状态单独建模 |
| Markdown | react-markdown + 代码高亮 | 消息渲染 |
| SSE | fetch + ReadableStream 自实现 | 需要 POST body + 自定义头，原生 EventSource 不够 |
| 类型 | `@shared/types`（monorepo 内部包） | **直接导出 zod schemas**（前端表单校验复用同一份 schema，而非仅生成 TS 类型） |

## 四、核心页面详设

### 4.1 对话页（最重页面）

```
┌────────────┬─────────────────────────────────────────┐
│ 会话侧栏     │  Agent 名 + 类型标签        [任务中心入口] │
│ + 新会话    ├─────────────────────────────────────────┤
│ 会话列表     │            消 息 流                      │
│ (最近活跃)   │  用户气泡 / 助手 Markdown                 │
│            │  [思考▾] [工具卡片] [引用卡] [产物卡]       │
│            │  [确认卡：确认/取消]                       │
│            ├─────────────────────────────────────────┤
│            │  [📎] [输入框................] [停止/发送] │
└────────────┴─────────────────────────────────────────┘
```

**消息流渲染规则**

| 消息元素 | 渲染 | 交互 |
|---------|------|------|
| 开场白 | 会话首条用户消息前，Agent 开场白纯文本气泡（不解析 markdown） | 新会话态展示（无 conversationId 进入时即展示，首条消息发送时才创建会话）；TaskAgent 同理 |
| 助手文本 | Markdown（代码高亮/表格/复制） | 流式追加；消息 hover 显示**复制全文**按钮 |
| 思考过程 | 灰底可折叠块，流式时默认展开 | 完成后自动折叠 |
| 工具卡片 | 图标 + 工具名 + 参数摘要 + 状态灯（运行/成功/失败） | 点击展开完整入参/出参；失败卡片显示原因；"需配置凭据"卡片带跳转按钮 |
| 引用卡 | 文档名列表 + 展开 snippet 原文 | 完成时随 citations 事件出现 |
| 产物卡 | 文件名 + 大小 + [预览] [下载] | 预览打开 4.6 |
| 确认卡 | 工具名 + 入参摘要 + [确认] [取消] | 阻塞输入区；120s 倒计时 |
| 引导问题（P1） | 开场白下方可点击列表 | 点击**填入输入框**（可编辑后发送），不直接发送 |
| 排队提示 | "沙箱并发已满，排队第 N 位" | queued 事件驱动 |

**会话侧栏**：会话项 hover 浮出 [重命名][删除]；重命名行内编辑；删除走分级确认（见 §七全局交互规范）。

**P0 隐藏项**：📎 附件按钮（P1）、[任务中心入口]（P1）——P0 版式图中不渲染。

**输入区状态机**

```
idle → streaming（发送→SSE建立）
输入约定：Enter 发送 / Shift+Enter 换行；streaming 中允许继续输入但发送禁用
streaming: 按钮变 [停止]；confirm 到达 → 锁输入显示确认卡
停止时序：点[停止] → POST /stop → 等 done{STOPPED} 收口；5s 未收口才 abort fetch，随后拉历史对齐
CONFLICT（同会话并发发送）→ toast "该会话正在生成中"
停止/完成 → idle
断线 → 顶部黄条提示，点击黄条=立即拉取历史对齐；
        TaskAgent 断线先查 GET /active（排队位次/当前工具）恢复进度视图，再拉历史
```

**TaskAgent 差异**：消息流同构（工具卡片 kind=SANDBOX）；右侧/下方多一个**产物面板**（artifact 事件驱动，列出文件+预览入口）；断线重连先查 `/active` 恢复进度（见输入区状态机）。

### 4.2 智能体编辑页

分区表单（单页滚动，不做多步向导）：

1. **基本信息**：名称/描述/图标上传/类型（ChatBot / TaskAgent，创建后不可改）
2. **模型**：下拉（`GET /api/models?type=CHAT`），显示上下文长度/是否支持图片
3. **提示词**：系统提示词（多行）；开场白；引导问题（可增删的列表）
4. **组件绑定**：
   - 知识库：多选框（列出全部 KB）
   - MCP：多选框（列出全部 server；**旁标"未配置凭据"红点**，点击去 `/mcp/credentials?serverId=…`）
5. 保存：`PATCH /api/agents/:id` + `PUT .../components`
   两个请求**串行执行**；任一失败 message.error 并停留页面、标注未保存区块（不静默部分成功）；成功后返回列表

### 4.3 知识库详情页

- 顶部：面包屑返回（知识库列表 → 详情）；名称/描述/检索配置编辑 + [上传文档] [检索测试]
- 文档表格：文件名 / 状态（解析中 spinner、完成 ✓、失败 ✗+原因）/ chunk 数 / 更新时间 / 操作（覆盖重传、重试、下载原始文件、删除）
- 检索测试抽屉：输入 query → 结果表（内容片段 / 向量分 / 全文分 / RRF 融合排名 / 命中库）

### 4.4 MCP 管理页

- Server 表格：名称 / endpoint / 工具数（缓存）/ 状态 / [测试] [编辑] [删除]
- 注册/编辑弹窗：基本信息 + **凭据参数模板编辑器**（行编辑：key / label / 注入位置 HEADER·QUERY·BODY）
- 「我的凭据」入口常驻此页顶部（徽标显示未配置数量）

### 4.5 我的凭据页

- 顶部：面包屑返回；支持 `?serverId=` 定位（自动滚动 + 高亮该 server 分组），可从 Agent 编辑页/工具失败卡片直达
- 按 server 分组的表单：每个 credential 参数一行（label + 密码框 + 已配置✓）
- 保存单个 server 的凭据；未配置的 server 置顶提示
- 明确提示："凭据仅用于代表你调用该工具，不会展示给他人"

### 4.6 文件预览（概要，详见子方案④）

| 格式 | 方式 |
|------|------|
| MD | react-markdown 渲染（消毒） |
| HTML | sandbox iframe（禁 script）+ CSP |
| 图片 | 直出 |
| CSV | 解析为虚拟滚动表格 |
| PDF | 浏览器原生 viewer |

预览统一为抽屉/全屏弹层，带下载按钮。

### 4.7 任务中心（P1）

TaskAgent 会话视图：任务（=会话）/ Agent / 状态（排队·运行·空闲回收·完成）/ 最近活动 / [继续对话] [停止]

## 五、SSE 事件 → UI 映射

| 事件 | 处理 |
|------|------|
| delta | 追加当前流式消息文本 |
| thinking | 追加思考块 |
| tool_call | 按 callId upsert 工具卡片，status 驱动状态灯 |
| confirm | 插入确认卡，锁输入区，倒计时 120s |
| citations | 挂到当前消息尾部引用区 |
| artifact | 产物面板追加条目 |
| queued | 顶部排队提示（含位次） |
| ping | **静默忽略**（保活心跳） |
| done | 结束流；finishReason=STOPPED 标注"已停止"（COMPLETE 为正常结束）；刷新会话列表排序 |
| error | 错误 toast + 消息流内错误卡；释放输入区；CONFLICT 专用文案"该会话正在生成中" |

历史还原：`GET /messages` 的结构化 jsonb 直接映射为上述卡片（与事件流同一套渲染组件，**单一渲染路径**）。

## 六、工程结构

```
frontend/src/
├── app/            路由、布局、鉴权守卫
├── pages/          login / agents / chat / knowledge / mcp / tasks / admin / settings
├── features/chat/  对话域组件：MessageList / ToolCard / CitationCard /
│                   ConfirmCard / ArtifactPanel / ChatInput / useChatStream
├── components/     通用组件（预览器、上传、空态）
├── api/            按模块的请求封装（TanStack Query 底座）；
│                   含统一错误码→文案映射层（BUSY/CONFLICT/NEED_CREDENTIAL…）
├── stores/         zustand（会话侧栏、SSE 流状态、全局 UI）
└── types/          re-export @shared/types
```

关键约定：
- **流式渲染与历史渲染同一套组件**（避免两套实现漂移）
- SSE 状态集中在 `useChatStream`（fetch 流解析 → store 分发），页面组件只读 store
- 组件内不写请求，全部走 api 层 hooks

## 七、全局交互规范（14 页面共用，前端开工前定稿）

> 目的：所有页面一套操作模式，避免各自实现后体验割裂。本节为评审回写新增（04-评审报告第七节）。

| 规范 | 约定 |
|------|------|
| 创建/编辑形态 | 字段 ≤6 的实体用**弹窗**（KB、MCP server、用户、模型）；字段多/分区表单用**独立页**（Agent）；同一实体创建与编辑同形态 |
| 删除分级确认 | 普通删除（文档/凭据/server）= Popconfirm；**级联删除（Agent/会话）= Modal + 红色危险按钮 + 明示影响范围**（如"将同时删除 N 个会话"） |
| 保存语义 | 显式保存按钮；失败停留页面 + 标注未保存区块（不静默部分成功）；成功 message + 返回列表 |
| 反馈通道 | 成功 = message 轻提示；失败 = notification（含错误码）；全局封装于 api 层 |
| 二级页动线 | 统一面包屑/左上返回（列表名 → 详情）；浏览器后退兜底 |
| 表格规范 | 操作列固定右侧、文字链按钮、危险操作红色、删除放最后；>3 个操作收进"更多"菜单；分页默认 20 |
| 列表三态 | 空态带引导按钮（"还没有智能体 → 去创建"）；加载骨架屏；错误带重试 |
| 文案词表 | 界面统一"智能体"（不与"Agent"混排）；创建实体/新建会话/注册 server 等动词按 01 需求表用语 |
| 键盘约定 | Enter 发送（对话输入框）/ Esc 关闭弹窗与抽屉 |
| 窄屏边界 | 桌面优先，设计基准 ≥1280px；<1024 不做适配仅保证可用 |
