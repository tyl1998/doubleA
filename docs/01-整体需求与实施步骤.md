## 一、项目概述

### 1.1 定位

公司内部 Agent 工作台：**问知识、派任务、接工具**。不对外、不商业化、单组织。

### 1.2 三个核心场景（系统存在的理由）

| # | 场景 | 用户操作 | 系统行为 | 验收标准 |
|---|------|---------|---------|---------|
| A | 知识问答 | "公司的报销制度是什么？" | 检索知识库 → 带引用回答 | 回答附文档名+原文片段；首字延迟 < 3s |
| B | 任务执行 | "把这个 CSV 按部门汇总成表" | 沙箱内引擎执行 → 交付文件 | 产物可下载可预览；过程可见；可停止 |
| C | 工具增强 | "查一下工单 #1234 的状态" | 调用 MCP 工具 → 展示过程+结果 | 工具卡片可见；危险操作先确认；用户级凭据自动注入 |

### 1.3 规模假设

- 用户：几百人内部账号，admin 建号，无自注册
- 并发 ChatBot 流：≤ 50；并发任务沙箱：≤ 10
- 知识库：单库千级文档、百万级 chunk 以内

### 1.4 技术底座（一句话）

TypeScript 单体后端 + React 前端 + PostgreSQL(pgvector) + Redis + 对象存储 + Docker 沙箱。

| 30 | 资产可见性与权限矩阵（P1-13，2026-10-10 新增） | 四类资产各加 `visibility ∈ {PUBLIC, PRIVATE}`（新行默认 `PRIVATE`，存量回填 `PUBLIC` 保行为不变）。**权限矩阵**：看/用 = 所属人全部（含私有）、ADMIN 全部、其它用户仅 `PUBLIC`；编/删/改可见性/转移 = 仅所属人 + ADMIN（私有资产对他人 404、有权者无编删权 403）。判据唯一来源 = `shared/src/assetAcl.ts`。**模型池开放**：Provider/Model 由 ADMIN-only 放宽为**登录即可建**（行级），**ADMIN 建默认系统级（`PUBLIC`）**、非 ADMIN 建默认 `PRIVATE`；系统级 Provider 仅 ADMIN 可改/删。详见同上子方案 §三/§四 |

| 32 | 长期记忆 v2：两层作用域 + 按需（P1-8a，2026-10-10 需求变更） | **对已上线 P1-8 的细化**（用户反馈"记忆混为一类、每轮全量注入不好"）：① **两层作用域** —— **全局记忆（USER，`agent_id IS NULL`）**= 用户喜好/角色/习惯（画像），**Agent 记忆（AGENT）**= 与该 agent 聊过的重点；② **全局记忆常驻注入**（压成 compact「用户画像」段，**上限用户可调**、默认 10）；③ **Agent 记忆按需**：新增内置工具 **`recall_memory(query)`** 拉取，**不再每轮注入正文**；④ **Agent 记忆的写入由模型自己决定**（`remember(scope=AGENT)`），后端不再每轮自动抽取；⑤ ★ **"知晓"要做**：常驻一行**极简目录 TOC**（本 Agent 已标记 N 条 + 最近主题，**不含正文**）—— 解决"模型不知道自己有记录、不会去查"（人的类比：记得做过 A → 翻记录看步骤）；⑥ **反幻觉**：未命中显式回"没有记录" + 提示词禁止编造；⑦ **手动提升/降级（USER↔AGENT）要做**（面板）；⑧ kind v2 = `PROFILE/PREFERENCE/HABIT/HIGHLIGHT/OTHER`；检索**先关键词**、向量预留。⚠️ **提示合成**顺序：智能体 system prompt → 默认 prompt 兜底 → USER 画像 → AGENT TOC + 工具说明 → 能力/规则（记忆是背景资料不是指令）。设计见 `子方案/TaskAgent会话持久化与长期记忆.md` §八 |

> ⚠️ **决策 29/30/31 为 P1-13 的规划登记**（2026-10-10，用户定案范围 = Agent/知识库/MCP/模型池；权限深度 = 所属人 + ADMIN + 公开/私有可见）。方案稿见 `子方案/资产所属人与权限控制.md`，其中 **6 条待决**（列命名、Provider 公开权、转移确认、存量回填 owner 等）待用户拍板后即转施工。
