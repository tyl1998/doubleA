## 一、项目概述

### 1.1 定位

公司内部 Agent 工作台：**问知识、派任务、接工具**。不对外、不商业化、单组织。

### 1.2 三个核心场景（系统存在的理由）

| # | 场景 | 用户操作 | 系统行为 | 验收标准 |
|---|------|---------|---------|---------|
| A | 知识问答 | "公司的报销制度是什么？" | 检索知识库 → 带引用回答 | 回答附文档名+原文片段；首字延迟 < 3s |
| B | 任务执行 | "把这个 CSV 按部门汇总成表" | 沙箱内引擎执行 → 交付文件 | 产物可下载可预览；过程可见；可停止 |
| C | 工具增强 | "查一下工单 #1234 的状态" | 调用 MCP 工具 → 展示过程+结果 | 工具卡片可见；危险操作先确认；用户级凭据自动注入 |

### 1.3 规模假设

- 用户：几百人内部账号，admin 建号，无自注册
- 并发 ChatBot 流：≤ 50；并发任务沙箱：≤ 10
- 知识库：单库千级文档、百万级 chunk 以内

### 1.4 技术底座（一句话）

TypeScript 单体后端 + React 前端 + PostgreSQL(pgvector) + Redis + 对象存储 + Docker 沙箱。

## 五、实施步骤（P 级别 + 依赖顺序）

### 阶段一：P0 问答闭环（场景 A）

依赖链从底向上：

```
1. 工程脚手架（monorepo/CI/配置加载/日志）
2. 认证与用户（登录/建号/会话）
3. 模型池（provider/model 管理 + LLM client 封装）
4. 知识库流水线（上传→解析→分块→embedding→入库；混合检索）
   ↳ 中文全文用 pg_bigm（PG 镜像需含 pgvector + pg_bigm）；复杂，拆子方案①
5. Agent 管理（CRUD + 组件绑定）
6. 对话编排（RAG 循环 + SSE 归一化 + 停止）
   ↳ SSE 协议全集见 02 文档；编排细节拆子方案②
7. 前端：登录/Agent 列表/编辑/对话页/知识库页
   ↳ 开工前 03《全局交互规范》定稿，14 页面共用
```

**出口验收**：admin 建号 → 用户登录 → 建知识库传 3 篇 PDF → 建 ChatBot 绑库 → 提问 → 带引用回答 → 停止 → 刷新恢复历史。全程无手工干预数据；首字延迟以服务端 TTFT 日志为准（< 3s）。

### 阶段二：P0 工具闭环（场景 C）

```
8. MCP client（2025-06-18 / Streamable HTTP / P0 无鉴权+用户级凭据，OAuth 2.1 为 P1）
9. 凭据机制（参数模板 + 我的凭据 + 注入）
10. 工具调用进编排循环 + elicitation 确认流
11. 前端：MCP 管理页 / 我的凭据页 / 确认卡片
```

**出口验收**：注册一个需要 token 的 MCP server → 用户 A 填自己的凭据 → 提问触发工具 → 凭据自动注入 → 确认卡片 → 结果返回；用户 B 未填凭据 → 工具标记"需配置"。

### 阶段三：P0 任务闭环（场景 B）

```
12. 沙箱镜像与生命周期（Docker SDK / 会话即容器 / 回收 / 排队）
    ↳ 复杂，拆子方案③
13. ACP 引擎桥接（会话启动 / 事件映射到 SSE / 停止）
14. 产物收集（工作卷扫描 → 对象存储 → 产物事件）
15. 文件预览（MD/HTML/图片/CSV/PDF，安全处理）
    ↳ 复杂，拆子方案④
16. 前端：任务型对话页（过程 + 产物面板）/ 预览
```

**出口验收**：建 TaskAgent → 派活"分析这份 CSV 出汇总表" → 沙箱过程可见 → 下载/预览产物 → 停止 → 会话恢复。
（⚠️ **"这份 CSV"的入口**：需求 35 文件附件与 `files` 表都属 **P1** ⇒ 2026-09-25 P0-3-0a 建议走**知识库文档**——后端起容器前把库里那份原始文件放进 work 卷（`02` §4.6 的下载端点 P0 已落地）⇒ 零需求变更。**此条待用户拍板**，见 `子方案/沙箱与引擎集成.md` §十三 待决 4。）

### 阶段四：P1 完善
