## 一、项目概述

### 1.1 定位

公司内部 Agent 工作台：**问知识、派任务、接工具**。不对外、不商业化、单组织。

### 1.2 三个核心场景（系统存在的理由）

| # | 场景 | 用户操作 | 系统行为 | 验收标准 |
|---|------|---------|---------|---------|
| A | 知识问答 | "公司的报销制度是什么？" | 检索知识库 → 带引用回答 | 回答附文档名+原文片段；首字延迟 < 3s |
| B | 任务执行 | "把这个 CSV 按部门汇总成表" | 沙箱内引擎执行 → 交付文件 | 产物可下载可预览；过程可见；可停止 |
| C | 工具增强 | "查一下工单 #1234 的状态" | 调用 MCP 工具 → 展示过程+结果 | 工具卡片可见；危险操作先确认；用户级凭据自动注入 |

### 1.3 规模假设

- 用户：几百人内部账号，admin 建号，无自注册
- 并发 ChatBot 流：≤ 50；并发任务沙箱：≤ 10
- 知识库：单库千级文档、百万级 chunk 以内

### 1.4 技术底座（一句话）

TypeScript 单体后端 + React 前端 + PostgreSQL(pgvector) + Redis + 对象存储 + Docker 沙箱。
